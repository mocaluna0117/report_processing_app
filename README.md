# Folio（フォリオ）

住宅アフターメンテナンスの報告書処理アプリ。**定期点検**・**アフターメンテナンス**・**顛末書**・**専決決裁書**・**捺印決裁書**の5つの画面があり、上部のタブで切り替えます（いま開いている画面の名前は左上の「Folio」の横に出ます）。

## 定期点検

写真報告書と点検報告書のPDFをブラウザにドラッグ&ドロップすると、

1. **写真報告書 → 点検報告書の順に結合したPDF** を作成してダウンロードでき、
2. **写真報告書から抽出した情報を、転記先Excelの列構成そのまま（1報告書=1行）** でコピーでき、
3. **依頼メールの文面**と**完了報告書（Excel / PDF）**もそのまま取り出せる

ローカル実行のWebアプリです。PDFの解析・結合は**すべてブラウザ内**で行われ、ファイルが外部へアップロードされることはありません。

## アフターメンテナンス

お客様から直接お問い合わせがあった補修の受付です（`/after`）。顧客データベースからお客様を選び、コールセンターの受付内容を貼り付けると、Excel転記用の行・メール文・完了報告書を作れます。2台で使うときは[共有フォルダー](#共有フォルダー2人で手直しと学習を共有する)で手直しと学習した書き方を分け合えます。詳しくは[アフターメンテナンス受付](#アフターメンテナンス受付)を参照してください。

## 顛末書

楽楽精算で最終承認まで進んだ顛末書のPDFを、本体と添付書類を1つに結合して取得します（`/tenmatsu`）。取得したあとの手作業（実行予算の入力・クラウド格納）の進み具合もチェックで記録できます。**PCにツールを入れる必要はありません。** ブラウザ（Chrome / Edge）で開き、保存先フォルダーを選んで、アカウントの画面で楽楽精算のIDとパスワードを一度だけ登録すれば使えます（取得のときに Folio が自動でログインします。3つの書類で共通です）。詳しくは[顛末書の取得](#顛末書の取得)を参照してください。

## 専決決裁書

楽楽精算で最終承認まで進んだ専決決裁書のPDFを、顛末書と同じやり方で取得します（`/senketsu`）。保存先フォルダーと一覧が顛末書とは別になります。詳しくは[専決決裁書の取得](#専決決裁書の取得)を参照してください。

## 捺印決裁書

楽楽精算で最終承認まで進んだ捺印決裁書のPDFを取得します（`/natsuin`）。取得のやり方は顛末書と同じです。
**すべての捺印決裁書には、あとから利用者がアップロードする書類が必要**なので、取得したものは「アップロード待ち」で一覧に入り、
書類を入れて確定すると、紐づく専決決裁書と1つのPDFになって保存されます。書類は複数入れられ、順番も決められます。
確定したあとでも「差し替え」で入れ直せます。詳しくは[捺印決裁書の取得](#捺印決裁書の取得)を参照してください。

## 使い方

```bash
npm install
npm run dev
```

ブラウザで <http://localhost:3502> を開き、写真報告書・点検報告書のPDFをまとめてドロップしてください。

開発サーバーは **3502番** を使います（3000番は他のプロジェクトと取り合いになりやすいため）。
会社のPCなど**別の端末から画面を確かめたい**ときは、同じネットワークの中で HTTPS で開けます。

```bash
npm run dev:lan              # このPCのLANアドレスで HTTPS 起動する
npm run dev:lan -- --print   # 開くURLを出すだけ
```

証明書はこのPCが自分で作ったものなので、別の端末では警告が出ます。「詳細設定」→「アクセスする」で進めます。
`npm run dev:lan` の間は、このPC自身も `localhost` ではなく表示されたアドレスで開きます。
ファイル名（例: `20260722 【写真報告書】山田　太郎様邸.PDF`）から自動でペアリングされます（手動修正も可能）。ファイル名の例はドロップ欄にも出しています。

### 画面の案内（初めて使う人向け）

どの画面も、上に**手順バー**が出ます。①②…の段に「完了 / いまここ / まだ」が付き、下の行に「**次にすること**」が1行出ます。段を押すと、その欄まで画面が動きます。

- 何も始めていないときは、手順バーの下に「**はじめて使う方へ**」として各段の説明が出ます。使い始めると自動で畳まれます（消すための操作は要りません）。
- **押せないボタンには、その理由を文字で出します**（例「保存先フォルダーにつないでください →保存先フォルダーへ」）。マウスを乗せたときの吹き出しも今までどおり出ます。
- ★**楽楽精算のログインの小窓と、右上の「楽楽精算: ログイン中／未ログイン」は無くしました**（2026-09-25。ログインが2つあって紛らわしいという声を受けて）。
  楽楽精算のIDとパスワードは、右上の人の形のアイコン →「アカウント」の「**楽楽精算のIDとパスワード**」で一度だけ登録し、
  取得のときは Folio が自動でログインします（[楽楽精算のIDとパスワードの登録](#楽楽精算のidとパスワードの登録)）。
  顛末書・専決決裁書・捺印決裁書の画面には、登録の状態を「楽楽精算」の1行で出します。
- 右上の「**共有フォルダー: 接続済み／未接続／未設定**」で、共有フォルダー（2台で分け合うデータベース）とのつながりがどの画面からでも分かります（2026-09-23）。
  押すと共有フォルダーの欄がモーダルで開き、どの画面からでもつなげます。つながりは Folio 全体で1つです。
  **未接続・未設定は、共有フォルダーのデータを使う3つの画面（定期点検・アフター・顛末書）でだけ目立たせます**（[いつ同期するか](#共有フォルダー2人で手直しと学習を共有する)）。
- ログアウトは右上の**人の形のアイコン**の「**Folio からログアウト**」だけです。このタブの楽楽精算のログインも一緒に忘れます
  （登録した楽楽精算のIDとパスワードはこのPCに残りますが、その人の Folio のアカウントでしか使えません）。
- 右上の「**使い方**」を押すと、画面を切り替えずに**モーダル**で使い方が開きます（`components/help-dialog.tsx`）。
  上のタブで画面を選び直せます。手順バーの「使い方を見る」を押すと、その画面のタブが最初から選ばれた状態で開きます。
  手順の文言は画面の手順バーと同じものを使っているので、画面と説明がずれません。
- 「Folio」の見出しと同じ行の右端の**人の形のアイコン**を押すと、名前・ログインID・「アカウント」・「問い合わせ」・「Folio からログアウト」が出ます（2026-09-24。「問い合わせ」は 2026-09-25 にヘッダーの段から移しました）。「アカウント」から、自分のパスワードを変える・楽楽精算のIDとパスワードを登録することができます（管理者は、人を足す・仮のパスワードを出す・止めることも。[ログイン](#ログインfolio-自体のアカウント)）。
- 右上の人の形のアイコン →「**問い合わせ**」から、不具合・改善の要望・質問を開発者へ送れます（2026-09-24。[問い合わせ](#問い合わせ不具合要望を開発者へ送る)）。
  「使い方」の小窓のいちばん下からも開けます（手元でアカウントを使わないときは右上のメニューが出ないので、こちらから開きます）。
- 「使い方」の各画面には**実画面の写真＋番号の印**も載せています（2026-09-22）。写真は架空のデータで撮った14枚だけで、
  文言は `lib/help-shots.ts`、寸法と印の位置は `lib/help-shots.generated.ts`（撮影スクリプトが書く）にあります。

#### 「使い方」の写真を撮り直す

画面を直したら、次のコマンドで撮り直せます（端末の Chrome / Edge を借ります。開発サーバーが動いていなければ自分で起こします）。

```bash
npm run help:shots               # 14枚すべて撮り直す
npm run help:shots -- tenmatsu-list   # id を指定すると、その1枚だけ撮る（generated.ts は書き換わらない）
npm run help:shots -- --format=png    # WebP ではなく PNG で撮る（差分調査用）
```

- 写す状態はすべて**架空のデータ**です（`scripts/help-shots/fixtures.ts`）。実在の氏名・住所・電話・伝票№・社員番号を写さないでください
- 撮った範囲の文字を自動で調べ、社員番号の形・テナントのホスト・許可外の氏名や電話番号が見つかると**その場で撮影を止めます**
- **撮り終えたら `.cache/help-shots/review.html` を開いて、全14枚を必ず目で確かめてください**（公開リポジトリなので、一度 push した画像は履歴から消せません）
- フォントは端末で変わる（macOS は Hiragino、Windows は Meiryo）ので、**14枚は同じPCで一度に**撮り直してください
- Chrome / Edge が無い環境では「飛ばしました」と出て、いまの画像のまま終わります（既存のテストと同じ流儀）
- 印の文言だけを直したいときは `lib/help-shots.ts` を編集するだけで、撮り直しは不要です（位置・寸法だけが `generated.ts` 側）

### 問い合わせ（不具合・要望を開発者へ送る）

画面右上の人の形のアイコン →「**問い合わせ**」（または「使い方」の小窓のいちばん下）から、不具合・改善の要望・質問を開発者へ送れます。開いていた画面が最初から選ばれます。

**届くまでの道**: ブラウザ → Folio のサーバー（`/api/contact`）→ メール送信のサービス **Resend** → 開発者の Gmail。
送り先のアドレスはサーバーの環境変数 `CONTACT_TO` にだけあり、**コードにも画面にも出しません**（公開リポジトリのため。`tests/contact-form.test.ts` が見張っています）。

| 送るもの | 送らないもの |
| --- | --- |
| 種類・画面・内容・お名前（任意） | 楽楽精算のログインID・パスワード |
| 写真（3枚まで。長い辺 1600px の JPEG に縮め、撮影情報は消えます。ファイル名は「写真1.jpg」などに置き換えます） | 共有フォルダーの名前・取り込んだファイルの名前・取得のログ |
| 一緒に送る情報: ブラウザ・画面の大きさ・楽楽精算にログイン中か・共有フォルダーの状態・Folio の版・日時 | 顧客データ・受付一覧（画面の中身は、写真に写したものだけ） |

- ★**お客様の氏名・住所・電話番号は書かないでください。** 電話番号・メール・郵便番号・住所・「〜様」らしき文字があると注意が出て、「伏せ字にする」で伏せられます（見つけられないこともあります）
- ★**写真は文字のように調べられません。** 写真を付けると、「写っていないことを確かめました」の印を押すまで送れません。写っているときは、その部分を切り取ってから付け直してください
- 送った内容は **Resend にも記録が残ります**（Resend のダッシュボードで見られます。Gmail と同じく開発者のアカウントの中です）
- 書きかけは**このタブのメモリにだけ**残ります（閉じても消えず、送れたら消えます。読み込み直すと消えます）。ブラウザには保存しません
- 送れないとき（Folio のログインが切れた・設定が無い・上限）は理由が出て、「**文面をコピー**」でメールやチャットに貼って送れます
- 上限は、Resend の無料枠で **1日100通・月3,000通**。押し間違いの連打を止めるため、サーバー1台あたり **10分に5通**までにしています

### 処理するペアを選ぶ

ペアリング結果の左端のチェックで**処理するペアを選び**、「選択した3件を処理」で実行します。

- **まだ処理していないペアだけが最初からチェックされます。** あとからPDFを足したときは**足した分だけ**が選ばれるので、そのまま実行すれば前の報告書を作り直しません（Excelに貼るときの重複も起きません）
- 状態の列に **未処理 / 処理済み / 処理に失敗 / 重複の可能性 / 写真報告書なし** が出ます。「未処理をすべて選ぶ」「処理済みも含めて選ぶ」「選択を解除」でまとめて選べます
- **処理済みにチェックを入れればやり直せます。** 確認が出て、**同じ行が新しい結果に置き換わります**（行は増えません。直したセル・カナ・完了報告書の設定は新しい結果に入れ替わります）
- **同じ施主・点検日の処理済みがあるペア**（再ダウンロードした `(1)` 付きのPDFなど）は「重複の可能性」と出し、既定ではチェックを外します（処理すると行がもう1つ増えるため）
- **写真報告書が無いペアは処理できません**（点検報告書だけでは抽出できないため）。プルダウンで写真報告書を選ぶとチェックできるようになります
- **処理した分は消えません。** 次に足したPDFを処理しても、前の抽出結果はそのまま残ります（消すときは行ごとの「削除」か「保存データを消去」）
- 取り込みのときに同じファイル（名前と大きさが同じ）は飛ばし、「4件を取り込みました (同じファイル1件は…)」と件数を出します

### 抽出結果の表示範囲

処理が終わると、抽出結果は**今回処理した分だけ**が出ます。見出しの下の切り替えで「すべて」に戻せます。

- **「Excel用にコピー」「結合PDFを一括DL」「監督・営業をまとめて反映」は、表示中の行が対象です。** 「今回の3件」のまま貼れば、前に貼った行を二重に貼りません
- 再読み込みすると「今回」が無くなるので、すべての行が出ます

「処理実行」後、結果テーブルの「Excel用にコピー」で表示中の行をまとめてクリップボードへコピーし、Excelに貼り付けます。左端の「行をコピー」ボタンで1行だけコピーすることもできます（行コピーにはヘッダー行は付きません）。

結果テーブル右端のボタンから、行ごとに結合PDF・メール文・**完了報告書（Excel / PDF）**も取り出せます。

- 結合PDFのボタンは**「〇年目点検報告書をDL」**（受付種別＝点検時期から。時期が読めなければ「点検報告書をDL」）で、保存されるファイル名と同じ言い方になります。実際の保存名はボタンにマウスを乗せると出ます
- ボタンの横の**「プレビュー」**で、ダウンロードされるPDFをそのまま開いて中身を確かめられます（拡大・印刷もできます。その場でダウンロードもできます）
- 完了報告書のダイアログには**ダウンロードされるPDFのプレビュー**が並びます。見出しや指示内容を直すとその場で作り直され、「ダウンロード」では**そのプレビューと同じPDF**が保存されます（「大きく表示」で拡大）
- プレビューの作成・表示はすべてブラウザ内で行われ、PDFが外部へ送られることはありません

不要な報告書は行ごとの**「削除」**で消せます。押すと確認が出て、その報告書の**抽出結果・アップロードしたPDF・ペアリング・結合PDF**がまとめて消えます（取り消せません）。抽出結果だけを消すと次の「処理実行」で戻ってきてしまい、PDFだけ残すと次にファイルを足したときの再ペアリングで復活するため、4つまとめて消しています。処理中は削除ボタンを出しません。

### 再読み込みしても消えません

アップロードしたPDF・ペアリング・抽出結果（結合PDF・メール文のカナ・連絡先を含む）は、**このブラウザの IndexedDB に自動保存**されます。誤ってタブを閉じたり再読み込みしても、開き直せば途中の状態から続けられます。Geminiの無料枠を再消費せずに済むよう、要約や工事区分の判定結果もそのまま復元されます。

- 保存先は**この端末のこのブラウザの中だけ**です。サーバー（Vercelを含む）には送信されません
- 顧客情報（氏名・住所・電話番号・PDF本体）が端末に残るため、**作業が終わったら画面下部の「保存データを消去」**を押してください。共有端末では特に必ず消去してください（1件だけ消すときは結果テーブルの行ごとの「削除」を使います）
- 「保存データを消去」が消すのは**定期点検の分だけ**です。アフターメンテナンスの顧客データ・受付一覧は、それぞれの画面の「顧客データを削除」「受付一覧を消去」で消します（毎回顧客データを取り込み直さずに済むようにしています）
- **学習した書き方**（[書き方を学習させる](#書き方を学習させる)）も「保存データを消去」では消えません。専用の「学習した書き方を消去」か、一覧の「削除」で消します
- 別のブラウザ・シークレットウィンドウ・別端末には引き継がれません
- 保存に失敗した場合（容量不足など）は画面に警告が出ますが、作業自体は続けられます。容量が足りないときは「保存データを消去」で古い分を消してから続けてください（書体を登録している場合は「書体の登録を消す」でも空けられます）（画面下部に保存量の目安が出ます）
- **抽出結果は消すまで積み上がります。** ファイルを足しても前の分は消えません（ペアリングのIDを引き継ぐので、処理済みかどうかも残ります）。溜まったら行ごとの「削除」か「保存データを消去」で減らしてください
- 以前の版（ファイルを足すとペアのIDが振り直されていた頃）の抽出結果が残っている場合は、抽出結果の上に「ペアリングに残っていない抽出結果が N件あります」と出ます。コピーやダウンロードはできますが、取り直すにはそのPDFを入れ直してください（その場で削除もできます）
- 前回の内容が読み込めなかった場合は、そのタブでは**保存を停止**します（空の状態で保存データを上書きして失わないため）。再読み込みすると復元をやり直せます
- 複数のタブで同時に開くと、後から保存した内容で上書きされます。1つのタブで作業してください

| 最終更新日 | 処理実行日（日本標準時）を「8月26日」形式で自動入力 |
| 備考欄 | 「8/26　点検報告書作成」（処理実行日・日本標準時）を自動入力 |

空白列も含めてタブ区切りで出力されるため、シートの左端の列（物件数）にカーソルを置いて貼り付ければ全列が正しい位置に入ります。物件数の★は記録1件に1つだけ付くので、★の数を数えれば貼り付けた報告書の件数（展開後の行数ではなく報告書の数）になります。

セルの色: **黄 = 要確認（警告付きで抽出）** / **赤 = 抽出失敗（手動入力してください）**。セルは直接編集できます。

アルファベットと数字は、すべての出力（Excel列・点検内容・結合PDF名）で**半角に正規化**されます（例: `Ａ号棟`→`A号棟`、`ＳＥＣＵＲＥＡ`→`SECUREA`）。

### 事業者の判定ルール

1. 契約番号が **21** 始まり → 必ず「タカマツハウス」
2. 契約番号が **31** 始まり → 必ず「賃貸住宅事業部」
3. 契約番号が **41** 始まり → その他事業者。現場名から判定（【】内の名称、ＳＥＣＵＲＥＡ＝大和ハウス工業）。判定できない・矛盾する場合は空欄＋警告（手動入力）
4. 契約番号で判定できない場合は現場名から: 【】内 → ＳＥＣＵＲＥＡ＝大和ハウス工業 → 「数字.」始まり＝タカマツハウス → その他＝賃貸住宅事業部

契約番号の規則と現場名からの推定が食い違う場合は、値に警告（黄セル）が付きます。ルールは [lib/pdf/parse-photo-report.ts](lib/pdf/parse-photo-report.ts) の `resolveDeveloper` にまとまっています。

### 工事区分の判定（点検報告書の画像認識）

点検報告書は手書きのチェックシートを撮影したPDFなので、テキスト層では読めません。そのため **Gemini（画像認識）** で「不具合」列の「有」に丸が付いた行を判定し、その項目名を工事区分（[lib/work-categories.ts](lib/work-categories.ts) の30区分）に対応付けます。

- 工事区分が複数ある報告書は、**工事区分の数だけ行を展開**して出力します（物件数の★は先頭の行だけ、他の列は同じ値）。0件なら工事区分が空欄の1行です
- 結果テーブルでは同じ報告書の行がまとめて表示され、プルダウンで工事区分の修正・追加（＋）・削除（✕）ができます。画像認識が自信なしと判定したものは黄色で表示されます

#### 点検内容は工事区分ごとに分かれます

工事区分が2件以上ある報告書では、「点検内容」が**行ごとの入力欄**になり、区分ごとに別の内容を書けます（貼り付けたときも行ごとの内容が入ります）。切り替えのボタンはなく、**工事区分の数で自動的に決まります**。

- 中身は**事象の文に出てくる工事区分名・別名で自動的に振り分け**られます（「クロスに凹凸」→ クロスの行、「換気扇から異音」→ 換気システムの行）。区分名が出てこない事象は「その他」の行、無ければ先頭の行に入るので、必要なら欄をまたいで書き直してください
- 振り分けが走るのは**処理した直後**と**工事区分を1件から2件に増やしたとき**です。区分を選び直しても本文は動かしません（手で直した内容を壊さないため）
- 点検員メモ（「メモ: …」）と「不具合の指摘なし」の定型文は先頭の行にだけ付きます
- **メール文・完了報告書・書き方の学習は全行をまとめた内容**になります（区分の順に並べ直して①②③を振り直します）。完了報告書ダイアログの指示内容は**工事区分ごとのグループ**で並び（番号は通し）、直した項目はその区分の行にだけ書き戻されます
- 工事区分を消して1件以下になると、残った行の内容が共通の欄にまとまります（消した行の内容は残りません。本文が入っている行を消すときは確認が出ます）
- 「処置」欄は分かれても報告書ごとに1つです（Excelに貼ってから記入する欄のため）
- Geminiへ送る画像は、**下部の署名・電話番号ブロックを切り落としたチェックシート部分のみ**です（顧客契約番号・点検員名・手書きメモは写り込みます）
- `GEMINI_API_KEY` 未設定時は判定を行わず、警告を出して手動選択に任せます

> **無料枠の上限について**: Geminiの無料枠は**モデル単位で1日20リクエスト**です（実測値。公式はダッシュボード参照方式に変わり数値を非公開）。そこで本アプリは**実測で正解5/5だったモデルを順に使い、上限に達したら自動で次のモデルへ切り替えます**。既定のモデル列は次の3つで、合わせて**1日あたり約60件**まで自動判定できます。
>
> | 順番 | モデル | 実測 | 速度 |
> | --- | --- | --- | --- |
> | 1 | `gemini-3.5-flash` (MINIMAL思考) | 5/5 正解 | 約2.3秒 |
> | 2 | `gemini-3-flash-preview` (MINIMAL思考) | 5/5 正解 | 約2.3秒 |
> | 3 | `gemini-3.6-flash` (既定の思考) | 5/5 正解 | 約13.6秒 |
>
> 切り替えが起きた場合は「〇〇(1日の上限に到達) のため別モデルで判定しました」と警告に出ます。判定に使われたモデル名は、結果テーブルの「工事区分 N件」バッジにマウスを乗せると確認できます。すべて上限に達した場合は待たずに警告を出し、手動選択に切り替わります（他の列の抽出・結合PDF・要約は影響を受けません）。
>
> モデル列は `.env.local` の `GEMINI_VISION_MODELS` で変更できます（カンマ区切り、`モデル名:思考レベル` 形式。`default` でモデル既定の思考）。件数がこれを超える場合は Google AI Studio で従量課金を有効にしてください（公式のトークン計算式からの試算で1枚あたり0.1円未満）。
>
> なお lite系モデルは1日の上限が緩いものの、手書きの丸を正しく読めず精度が大きく落ちる（実測3/5）ため画像認識には使いません。要約には lite系を使っています。

### 引渡日を顧客データへ反映

写真報告書の引渡日は、アフターメンテナンスの顧客データ（xlsx由来）の引渡日より確かです。そこで**処理実行が終わった時点で、照合できた顧客の引渡日を報告書の値で自動的に更新**し、結果テーブルの下に何を更新したかを表示します。顧客データを取り込んでいないブラウザでは何も出ません。

- 照合はまず **PJ（契約番号）**で探し、点検保守台帳（DX）はPJの一致で確定、助っ人クラウドは**氏名か住所の裏取りが取れたときだけ**確定とします（助っ人クラウドのPJは管理IDからの変換なので別人と衝突しうるため）。PJで見つからない場合は**氏名と住所の2つが揃ったとき**に候補として出します
- 物件名の**棟・区画の記号が食い違う顧客には結び付けません**（A号棟とB号棟）。住所は「3丁目14番10号」＝「3-14-10」、台帳側に建物名や枝番が付いただけのものも同じ住所として扱います
- **自動更新は「照合が確実」なものだけ**です。次のものは自動では書かず、行ごとの「更新」ボタンで反映します
  - 照合が確実でない（PJのみ一致・氏名と住所だけの一致）
  - 報告書の引渡日が要確認（黄セル）
  - 顧客データ側で引渡日を手直し済み
- 自動更新した行は**「元に戻す」**で取り込み値に戻せます。「残りをすべて更新」で要確認の分もまとめて反映できます
- 反映した引渡日は**「手直し」として保存**されるので、顧客データを取り込み直しても残ります。顧客カードには「定期点検の報告書から更新」と出て、「取り込んだ内容に戻す」で取り消せます
- 顧客データはこのブラウザの IndexedDB にあるため、**顧客データを取り込んだ端末・ブラウザで処理**してください

### メール文のコピー

結果テーブル右端の「メール文」ボタンで、依頼メールに貼れるテキストを確認・コピーできます。

```text
【物件情報】
引渡日：2025/09/26
物件名：（物件名称）
施主名：山田　太郎（ヤマダ　タロウ）様
住所：（住所）
連絡先：090-0000-1234

【依頼内容】
①…
②…
```

- 物件名・施主名・住所・依頼内容は結果テーブルの現在値から作られるので、テーブルで直せばメール文にも反映されます。引渡日はメール文だけゼロ埋め（yyyy/mm/dd）です
- **施主名のカナは Gemini の推定です。** PDFに読みは無いため、漢字の氏名だけを Gemini に送って推定しています。読みが複数ありえる名前（裕子＝ユウコ／ヒロコ 等）や外国人名は黄色で候補を示すので、確認画面で必ず目視・修正してください（修正した値は保持されます）。キー未設定時は空欄になり、手入力します
- 連絡先は点検報告書のテキスト層（下部の電話番号欄）から抽出します。②の番号がある場合は「連絡先①：番号（続柄）」「連絡先②：番号（続柄）」の2行、①のみなら「連絡先：番号」になります。電話番号はブラウザ内でのみ扱い、外部には送信しません

### 完了報告書の作成（Excel / PDF）

**見出しの各欄（PJコード・引渡日・物件名・施主名・施主名のカナ・住所・連絡先①②・受付日・受付者）はモーダル内で直接編集できます。** 直した内容は結果テーブルの該当セル（連絡先はメール文と共通の値）にも書き戻されるので、テーブルに戻って直す必要はありません。受付者だけは完了報告書だけの値で、空欄にすると既定の「木村美恵子」で出力します（結果テーブルの「受付者」列とは別です）。

指示内容もモーダル内で直接編集でき（項目の追加・削除、項目ごとの**補足**の追加も可能。補足は1つの項目にいくつでも付けられます。2026-09-25）、直した内容は結果テーブルの「点検内容」（アフターメンテナンス受付では「アフター受付内容」）とメール文にも反映されます。工事区分が2件以上ある報告書では**工事区分ごとのグループ**で並び（番号は区分をまたいで通し）、直した項目はその区分の行にだけ書き戻されます。

補足は本文の中に `補足: …` の行として保存されます（項目のすぐ下の行。補足1つにつき1行。どこで直しても項目と補足がずれません）。報告書には、補足1つにつき頭に「・」を付けた行が1行ずつ載ります（先頭に「・」を打っても二重にはなりません）。「＋補足」を押しただけでは本文は変わりません（書いたときに入ります）。書き方の学習（手本）には補足を含めません。

結果テーブル右端の「完了報告書」ボタンで、社内様式の完了報告書を **Excel（.xlsx）と PDF** でダウンロードできます。どちらも保存名は `完了報告書（原紙）.xlsx` / `完了報告書（原紙）.pdf` 固定です。

| 欄 | 入る値 |
| --- | --- |
| PJコード / 引渡日 / 物件名 / 住所 / 受付日 | 結果テーブルの現在値（テーブルで直せば反映されます） |
| 施主名 | `姓　名（セイ　メイ）` ＋ Excelの表示形式が付ける「 様」。カナが空なら括弧ごと省きます |
| 連絡先①② | 点検報告書から抽出した電話番号（メール文と同じ） |
| 受付者 | 既定は「木村美恵子」。ダイアログの「受付者」欄で報告書ごとに変えられます |
| 立会 / 受付項目 | ダイアログのチェックボックスで選べます（既定は**点検のみ**）。変更はリロード後も保持されます |
| 指示内容 | 点検内容の各項目。**5件までは本紙に №①〜⑤ ＋ 本文**、**6件以上は本紙を「別紙参照」の1行だけにして、全件を別紙に記載**します。1行（全角41文字）に入らない項目は**次の枠に続き**を書き（続きの行の№は空。文字は小さくしません）、補足もその次の枠に「・…」として1つにつき1行ずつ書きます。折り返しや補足で**本紙の5つの枠に入らなくなったときも別紙**に回します（例: 項目2つに補足が2つずつなら別紙へ） |
| 作業内容・是正内容 以降 | 空欄のまま。**№だけは項目ごとに1行ずつ**入ります（指示内容と違い、折り返しの続き・補足では行を空けません。Excelでは数式ではなく値で入れます） |

- **Excel**: 同梱テンプレート `public/report/completion-report.xlsx` の「入力シート」「作業報告書　兼　完了報告書」「別紙」の3シートを保ったまま、必要なセルだけ書き換えます。本紙は入力シートを参照する数式のままなので、Excelで入力シートを直せば本紙も追従します（数式のキャッシュ値も書いているので、再計算しないビューアでも値が見えます）
- **PDF**: 見本PDFと同じ体裁をブラウザ内で描き起こしています（A4縦・罫線・チェックボックス・別紙ページ）。別紙は1ページ12件で、13件以上は別紙を複数ページに分けます（Excelの別紙シートは12件までなので、その場合は警告が出ます）
- **別紙の補足**: 補足のある項目だけ、項目の行の下に**細い欄**（行高15）を補足の数だけ作ってそこに書きます。ExcelもPDFと同じ形になるよう、別紙シートの枠の行・結合セル・印刷範囲を行数に合わせて組み立て直します（補足が無ければテンプレートのままです）。細い欄が増えた分、Excelの印刷が2ページに割れることがあります
- 生成はすべてブラウザ内で、テンプレートとフォントは静的ファイルの取得だけです（個人情報はサーバーへ送られません）。フォントは HarfBuzz（hb-subset）で **その報告書に出てくる文字だけに絞って**から埋め込むので、PDFは数十KBです

#### PDFの書体（游ゴシックにしたい場合）

既定は **Noto Sans JP（OFL-1.1、同梱）** です。見本と同じ **游ゴシック**にしたい場合は、完了報告書ダイアログの「PDFの書体」から**この端末に入っている游ゴシックを登録**できます。

- 游ゴシックは Windows / Microsoft Office に付属する書体で **再配布はできない**ため同梱していません。一方でフォント自身の埋め込み設定は `fsType = Editable`（埋め込み可）で、ライセンス表記も「このフォントに含まれる埋め込み制限の範囲で文書に埋め込んでよい」となっています。**ライセンスを持つ端末で自分の文書に埋め込むのは許可**されている、という前提の機能です（Excelの「PDFとして保存」と同じ扱い）
- 登録の仕方は2通り。Chrome / Edge なら「端末の游ゴシックを使う」（フォントへのアクセス許可を1回聞かれます）。他のブラウザではフォントファイルを選びます
  - Mac（Office同梱）: `/Applications/Microsoft Word.app/Contents/Resources/DFonts/YuGothR.ttc` と `YuGothB.ttc`
  - Windows: `C:\Windows\Fonts\YuGothR.ttc` と `YuGothB.ttc`
  - `.ttc`（複数書体入り）から適切な書体を自動で選びます（Yu Gothic UI などの派生は避けます）
- **一度登録すれば以後は自動的にその書体で作られます**（「保存データを消去」しても書体の登録は残ります。顧客データではなく設定として扱うため）
- 登録したフォントは**この端末の IndexedDB にだけ**保存され、外部には送信されません（約27MB）。画面下部の保存欄に内訳が出て、**「書体の登録を消す」**でいつでも消せます（完了報告書ダイアログの「同梱の書体に戻す」でも同じ）
- フォントに無い文字は「〓」に置き換えて警告します

## アフターメンテナンス受付

お客様がコールセンター等へ直接お問い合わせして発生する補修の受付です。画面上部の「アフターメンテナンス」タブ（`/after`）から使います。
画面の上に「①顧客データ ②お客様を選ぶ ③受付を登録 ④受付一覧」の手順バーが出ます（[画面の案内](#画面の案内初めて使う人向け)）。

### 1. 顧客データを取り込む

顧客情報の xlsx / csv をドロップすると、次の2形式を**自動で判定**して取り込みます。

| 形式 | 位置づけ | 取り込み方 |
| --- | --- | --- |
| 助っ人クラウド 顧客情報 | 旧システム。今後この形式でデータが増えることはない | **入れ替え**（同じ形式のデータを丸ごと差し替える） |
| 点検保守台帳（DX）顧客情報 | 今後の正。同じ列のファイルを追加していく | **PJ（物件番号）で追加・更新**（載っていない顧客は消さない） |

取り込まない行は、理由と行番号がまとめて表示されます（「物件名が×使用禁止×」「物件番号の末尾が01以外」「技術行」「内容が同じ行」「空行」）。

助っ人クラウドの**管理IDが「DX」の行**（点検保守台帳へ移した印）は、**落とさずに取り込みます**。台帳にも載っていれば下記の重複解消が消すので取りこぼしません。逆にここで落とすと、**台帳側が「×使用禁止×」だった顧客がどちらのファイルからも消えます**（実データに1件ありました）。

主な変換:

- **PJ**: 助っ人クラウドは管理IDから変換（`1234-5`→`1012340101`、`123-4`→`1101230101`、`12-3`→`1100120101`、`1-2`→`1100010101`、`B12-3`→`2100120301`）。**規則に当てはまらない管理ID（`DX`・物件名が入っているものなど）はPJを空欄にして「要確認」**にします（実データでは取り込み後1034件が該当）。点検保守台帳は物件番号をそのまま使います（`(BS)`付きは数字部分）
- **事業者**: 点検保守台帳は物件番号の先頭2桁から（10・11＝EU / 21＝タカマツハウス / 31＝賃貸住宅事業部 / 51＝倉庫事業）。41始まりは物件名から（SECUREA・セキュレア＝大和ハウス工業 / リーフィア＝小田急不動産 / 三鷹市下連雀＝コスモスイニシア / 北加瀬1丁目の家・鹿島田の家＝福禄不動産）。**判定できないものは空欄＋要確認**にし、画面で直します。助っ人クラウドは担当支店をそのまま（「エンドユーザー」→「EU」）
- **物件名称**: 「(仮称)」「新築工事」「分譲住宅」「（全N区画）」「（N区画）」「（BS）」「第N期M区画」を除き、半角カナ（ｾｷｭﾚｱ）を全角にします
- **氏名・カナ**: 姓名の間を全角スペースに揃え、カナはカタカナに直します（法人名は空白をそのままにします）。**連名は要確認にしません** — 「サトウ　ハナコ・サトウ　ジロウ」の「・」区切りに加え、「サワダ　イサム（タチバナ　ミキコ）」のように2人目を括弧で添える書き方（氏名欄が「澤田　敢（橘　幹子）」のとき）も正しい書き方として扱います。括弧は全角に、読点・半角中黒は「・」にそろえます
- **連絡先**: 「090-0000-0000（奥様）」のような続柄付きの番号を、番号と続柄に分けます。助っ人クラウドは携帯→固定、点検保守台帳は TEL1→TEL2 の順です
- **住所**: 点検保守台帳は「所在地住居表示」に「建物名」を全角スペースで続けます
- **郵便番号**: 点検保守台帳は「所在地住居表示 郵便番号」、助っ人クラウドは「建築地郵便番号」（空欄なら「現住所郵便番号」）から取り、`123-4567` の形に揃えます（全角数字・`〒`・ハイフンの有無・空白は吸収）。**7桁として読めない値は空欄にして要確認**に出します（推測で直しません）。郵便番号の列が無い古いファイルもそのまま取り込めます。**列が増えても顧客IDは変わらない**ので、再アップロードしても手直しは消えず郵便番号だけが増えます
- **監督・営業**: 営業は点検保守台帳の「営業担当 担当者(主)」から取り込みます。**監督はどちらのファイルにも列が無い**ので、[顛末書タブから反映](#顛末書の取得)するか、受付一覧の行に入力して**[「監督・営業を登録」](#監督営業をお客様の情報に登録)**で入れます
- **引渡日**: 点検保守台帳は **備考の「エンド引渡日：2025/3/10」→「築年月日」列** の順に見ます（どちらも無ければ空欄）。備考にはメール文の控えなど別の「引渡日：」も入るため、「エンド引渡日」の見出しだけを拾います。日付は `2025/3/10`・`2025-3-10`・`2025年3月10日`・`20250310`・全角数字・時刻付き・和暦（`令和7年3月10日`）・**Excelの日付書式のセル**のいずれでも読めます。エンド引渡日は**年と月の区切りが打ち間違いで抜けていても読みます**（`202310/30`→`2023/10/30`。月と日の区切りが残っていれば日付の切れ目は一意に決まるため）。読めない値は空欄にして、その値を要確認に出します

**要確認**の顧客は「要確認 N件」ボタンで絞り込めます。画面で直した内容は**取り込み値とは別に保存**されるので、同じファイルを取り込み直しても消えません（「取り込んだ内容に戻す」で戻せます）。

#### 監督・営業をお客様の情報に登録

**受付を登録すると、お客様の情報に入っている監督・営業がその行の「監督」「営業」列に入ります。**（お客様の情報が空欄なら、行も空欄のままです）

受付一覧の**監督・営業の列が空欄のとき**、その行に入力して右端の**「監督・営業を登録」**を押すと、そのお客様の情報に入ります。顛末書が無い現場でも、分かった時点で顧客データに貯められ、次に作る受付の行にも入るようになります。

- 入るのは**その受付のお客様1件だけ**です（同じ現場の別棟は書き換えません）。顛末書からの反映（PJの上8桁でまとめて）とは別の操作です
- **手直しとして保存**されるので、顧客データを取り込み直しても残ります（顧客カードに「手直し済み」と出ます。「取り込んだ内容に戻す」で戻せます）
- お客様の情報に**別の値が入っているときは、何が入れ替わるかを出して確認**します（黙って消しません）。同じ値が入っているときはボタンを押せません
- 押せないときは、ボタンにマウスを乗せると理由が出ます（行が空欄 / 同じ値が入っている / お客様が見つからない）

#### 両方に載っている顧客（点検保守台帳が正）

同じ物件が両方のファイルにあると重複して出てしまうため、取り込みのたびに全件を突き合わせ、**点検保守台帳（DX）を正として助っ人クラウド側を消します**。判定は `lib/after/dedup.ts`（純関数）です。

- 手がかりは **PJ・氏名・住所・物件名** の4つで、**2つ以上そろって初めて**同じ物件とみなします。1つだけの一致は当てになりません（助っ人クラウドの管理ID→PJ変換は規則が不完全で、実データでは**別人のPJと5組衝突**していました。「架空が丘4丁目A号棟」のように事業者違いで物件名だけ同じ例もあります）
- 照合では表記ゆれを吸収します。住所は「3丁目14番10号」＝「3-14-10」、台帳側に**建物名や枝番が付いただけ**（`…2-12-9SORA`、`44-1` と `44-1-3`）も同じ住所として扱います。氏名は法人格・肩書き・括弧書き、物件名は括弧書き・【】・「新築工事/新築計画」を落とします
- **住所がはっきり違うものは、他がそろっていても消しません**（同じ施主が別の場所に建てた2棟目がありました）。消さずに要確認として画面に出します
- **棟・区画の記号が食い違うものは結び付けません**（「A棟」と「B号棟」→ 記号 A / B で別の建物）。同じ敷地の別棟は施主も住所も同じなので、これが唯一の見分け方です。書き方の違い（`C棟` / `C号棟` / `A区画` / `5号地`）は吸収します
- 棟の記号が無くて相手を1つに絞れないときは、助っ人クラウド側の件数が台帳側**以下**なら全部が台帳に載っているとみなして消し、**多い場合は台帳に無い棟が混じっている**ので消しません
- 補完は**相手が1件に定まったときだけ**行います（どの棟の引渡日か取り違えないため）
- 消すときは、**台帳が空欄の項目だけ**を助っ人クラウドから補います（顧客カードに「助っ人クラウドから補完」と出ます）。台帳に値がある項目は常に台帳が勝ち、あとで台帳に値が入れば補完は外れます。実データでは台帳317件のうち123件が引渡日を持たず、**重複40件はすべて助っ人クラウドの引渡日で埋まりました**
- どちらを先に取り込んでも、何度取り込み直しても最終状態は同じになります

実データ（助っ人クラウド3671件 / 台帳317件）では **40件**が重複として消え、**1件**が要確認として残りました（合計3948件）。

### 2. 受付を登録する

お客様を検索（氏名・カナ・PJ・物件名・住所・電話番号。ひらがな/カタカナ・ハイフンの有無は区別しません）して選び、コールセンターの受付内容を貼り付けて「受付を登録」を押します。

- 受付内容は**不具合の事象**に要約されます（訪問日程・折り返しの約束・挨拶は落とします）。不具合が書かれていない依頼（「網戸を追加したい」など）は、**依頼の内容がそのまま入ります**（空欄で登録されないように）
- Gemini APIへ送るのは、**選んでいるお客様の氏名・カナ・電話番号・住所・メールアドレスを伏せ字にした受付内容だけ**です。キー未設定・通信できないときはブラウザ内の定型処理に切り替わります
- 段取りの連絡だけで内容が取り出せなかった場合は空欄になり、受付欄に理由が出ます（受付一覧の「アフター受付内容」に直接入力してください）

#### 書き方を学習させる

要約をそのまま使うことは少なく、たいてい少し書き直すことになります。**「この書き方を学習」**を押すと、その1件を（伏せ字にした入力 → 直したあとの本文）の組で覚え、**次回以降の要約で手本として Gemini に送ります**（文体・語尾・1件にまとめる粒度・用語がその書き方に寄ります）。

**定期点検とアフターメンテナンスの両方にあります。** 入力の形とプロンプトが違うので、手本の一覧は画面ごとに別々です。

| 画面 | ボタンの場所 | 覚える組 |
| --- | --- | --- |
| 定期点検 | 結果テーブルの行 | 不具合項目（場所・部位・症状・備考） → 点検内容 |
| アフターメンテナンス | 受付一覧の行 | 受付メモ → アフター受付内容 |

- ボタンは「この書き方を学習」→ 押すと「学習済み ✓」、そのあと本文を直すと「再学習」になります。本文が空欄のときは押せません。定期点検では、この機能を入れる前に処理した報告書（不具合項目の文を持たない行）も押せません
- 送るのは**今回の入力に近いものから最大8件**です（合計の文字数にも上限があるので、待ち時間はほとんど変わりません）
- 保存・送信するのは**伏せ字にした本文だけ**です（氏名・カナ・電話番号・住所・メールアドレスは、保存時と送信時にそれぞれ伏せ字にします）。表の上の「一覧・消去」で、保存されている本文をそのまま確認・削除できます
- 保存は各画面200件までで、超えると古いものから落ちます
- `GEMINI_API_KEY` 未設定時の定型要約には使われません（手本は Gemini へのプロンプトに載せるものなので）

### 3. 受付一覧から取り出す

定期点検と同じ結果テーブルですが、次の点が違います。

- **貼り付けは備考欄を除いた23列**（備考欄は定期点検の「点検報告書作成」用の欄のため）
- **受付種別・受付者はプルダウン**。受付種別の既定は未選択で、未選択のままコピーしようとすると確認が出ます。受付者の既定は「木村」
- **結合PDFはありません**（写真報告書・点検報告書が無いため）。行の「削除」で受付を取り消せます
- **メール文**の連絡先・カナは顧客データの値を使います
- **完了報告書**は受付項目の既定が「アフター」、別紙のタイトルが「アフターメンテナンス是正項目」になります（受付者欄の既定は定期点検と同じ「木村美恵子」で、ダイアログで直せます）
- **物件数には定期点検と同じく★**が入ります（工事区分を足して複数行に分かれても先頭の行だけ）

### PDFの名前を変えたとき

保存先フォルダーでPDFの**名前を変えても大丈夫**です（クラウドへ上げる前に分かりやすい名前にする、など）。

- 保存するとき、記録（`_記録`）にPDFの**中身の指紋（SHA-256 と大きさ）**も残します。名前で見つからないときは、保存先の直下から中身が同じPDFを探し、**記録の名前を今の名前に書き換えます**（一覧を読み込み直したときに「今の名前につなぎ直しました」と出ます）。以後はプレビュー・印・差し替えも今の名前で動き、**差し替えは名前を変えたファイルを上書き**します
- **推測はしません。** 同じ中身のPDFが2つある・ほかの記録のPDF・サブフォルダーへ移したもの、は結びません
- **この機能より前に取得した記録**は指紋が無いので、自動では結べません。「ファイルなし」の行の右端に出る**「PDFを選ぶ」**から、今の名前のPDFを選んで結んでください（中身を見て確かめられます）。以前の記録にも、一覧を読むたびに少しずつ裏で指紋を付けていくので、付いたあとは自動で結び直ります
- 記録の名前のPDFが見つからない行は、**差し替えを押せません**（以前は元の名前で別のファイルを作ってしまっていたため）。先に「PDFを選ぶ」で結んでください
- 名前を変えて空いた名前は、別の伝票の保存名には使いません（元の記録が別のPDFを指してしまわないように）

**保存名の「No.」を「№」に直す**（2026-09-16 に表記を変えました）

以前は `顛末書No.1476.pdf` の形で保存していました。以前の表記のPDFが残っていると一覧の上に案内が出るので、**「保存名を『顛末書№…』に直す」**を押すと、PDFの名前と記録をまとめて直します（中身と完了の印は変わりません）。同じ名前のPDFがすでにある・PDFが見つからない記録はそのままにして、件数を伝えます。すでにクラウドへ上げたファイルとは名前が違うことになるので、必要なら上げ直してください。

### 保存とプライバシー

顧客データ（数千件の氏名・住所・電話番号）と受付一覧は、**この端末のブラウザ内（IndexedDB）にだけ**保存されます。

- 定期点検の「保存データを消去」では**消えません**。毎回取り込み直さずに済むようにしているためです
- 消したいときは、この画面の**「顧客データを削除」「受付一覧を消去」**を使ってください。共有端末では作業後に必ず消してください
- 受付内容の原文もこの端末にだけ保存されます（要約のために送るのは伏せ字にした本文だけです）
- **学習した書き方**（伏せ字済みの入力と直した本文）も同じブラウザ内に保存されます。定期点検とアフターで別々の一覧です。設定として扱うため「受付一覧を消去」「保存データを消去」では消えず、**「学習した書き方を消去」**または一覧の「削除」で消します。共有フォルダーを使わずに移すときは、一覧の**「JSONで書き出す」「JSONを読み込む」**を使ってください

### 共有フォルダー（2人で手直しと学習を共有する）

Folio のデータはブラウザの中にあるので、そのままだと**2人目の端末は空から始まります**。画面右上の**「共有フォルダー」**（どの画面からでも開けます。アフターメンテナンスの画面にも同じ欄があります）で、2台から見える同じフォルダー（Box Drive など、PCのフォルダーとして見えるもの）を選ぶと、育ってきた分を分け合えます。**サーバーは立てません。** folio のサーバー（Vercel）へは、共有しても何も送りません。

**共有するもの・しないもの**

| 共有する | 共有しない |
| --- | --- |
| 顧客データの**台帳**（取り込んだ値そのもの） | 受付一覧・受付メモの原文 |
| 顧客データの**手直し**（直した項目だけ。氏名・電話番号を直せばその値を含みます） | 定期点検のPDF・抽出結果、フォント、楽楽精算のログイン情報 |
| 定期点検・顛末書から反映した引渡日・監督・営業 | |
| **学習した書き方**（アフター・定期点検の2種。伏せ字済み） | |

**使い方**

1. 共有ストレージに Folio 専用の**空のフォルダー**（例 `Folio共有`）を作り、2人で見られるようにします
2. 先に使っていた人が画面右上の「共有フォルダー」を押し、「共有フォルダーを選ぶ」→ そのフォルダーを選び、**「このフォルダーへ書き出す」**を押します（選び間違えたフォルダーにいきなり書かないよう、初回だけ確認します）
3. 2人目が同じフォルダーを選ぶと、そのまま同期されます
4. **顧客データの台帳は `顧客データ.json` で行き来します。** 取り込んだ値そのものが入っていて、取り込むたびに更新されます。2人目はフォルダーを選ぶだけで台帳ごと受け取れます（xlsx を取り込む必要はありません）
   - **id はそのまま運びます。** 助っ人クラウドの id は取り込み内容から作るので、作り直すと手直しが結び付かなくなります。作らずに運ぶので必ず一致します
   - **手直しは別のファイル**（`顧客の手直し.json`）です。台帳は取り込んだときにしか変わりませんが、手直しは直すたびに変わるので分けています
5. **はじめて使うときだけ**、顧客データの xlsx / csv を `_data` に置いてください。Folio が取り込んで `顧客データ.json` を作ります（以後はこのファイルが最新なので、xlsx は置いたままでも外しても構いません）
   - 置く名前は自由です。ファイルの見出しから、助っ人クラウドか点検保守台帳かを自動で判定します
   - **手で取り込む道も残っています。** 顧客が増えたときは、今までどおり「顧客データ」の枠にドロップして構いません。**共有フォルダーにつないでいれば、そのファイルを `_data` にも自動で置きます**（コピーし忘れると、もう1台だけ古い台帳のままになるため）。つないでいなければ、今までどおり取り込むだけです

   あとから顧客データを追加してドロップしたときの動きは、取り込み元で違います。

   | | この端末 | `顧客データ.json` |
   | --- | --- | --- |
   | 点検保守台帳 (DX) | 物件番号で**追加・更新**。前の分は消えません | **足し込みます**（片方しか取り込んでいない月も消えません） |
   | 助っ人クラウド | その取り込み元を**丸ごと入れ替え**。件数が減るときは先に確認が出ます | **あとから取り込んだ方の一式**になります（足し込むと、消したはずの行が戻ってしまうため） |

   落とした xlsx も `_data` に置かれます（もう1台が xlsx から入れ直したいときのため）。置いたファイルは取り込み済みなので、次の同期で読み直すことはありません。
   - ★**助っ人クラウドは、その取り込み元を丸ごと入れ替えます。** 置いたファイルで件数が**減る**ときは黙って入れ替えず、件数を出して確認のボタンを出します
   - ★**助っ人クラウドのファイルは1つだけ置いてください。** 2つ以上あると、どちらで入れ替わるか決められないので、**取り込みを止めて**画面に知らせます。点検保守台帳は物件番号で足し込むだけなので、何個あっても構いません（月ごとの差分を分けて置けます）
   - 顧客データでないファイルが置いてあっても、読めないものは飛ばします

**いま使っている人のデータを、もう1台へ渡すとき**

Folio は取り込んだ**ファイル自体を残していません**（読んで顧客データに変えたあと捨てます）。この仕組みより前に取り込んだ分は、元のファイルを手で置いてください。1回きりの作業です。

| 取り込み元 | 置くもの |
| --- | --- |
| 助っ人クラウド | **最後に取り込んだ1つだけ**（丸ごと入れ替わるため）。`_data` の中へ |
| 点検保守台帳 (DX) | **これまで取り込んだものを全部**（差分のことがあり、足し込むだけなので害はありません）。`_data` の中へ |

置いて一度同期すれば `顧客データ.json` ができるので、以後この作業は要りません。

置いたあと、2人のアフターメンテナンスの「顧客データ」の欄で、**助っ人クラウドと点検保守台帳の件数が一致していれば**同じ台帳です。
**いつ同期するか**

つながりは **Folio 全体で1つ**です（画面ごとにつなぎ直しません）。同期するのは、共有フォルダーのデータを使う画面だけです。

| 画面 | 開いたとき | 直したとき（少し待ってまとめて書き出す） |
| --- | --- | --- |
| 定期点検 | 相手の分を取り込む | 引渡日の反映（自動・手動・元に戻す）、学習 |
| アフターメンテナンス | 相手の分を取り込む | 顧客の手直し、学習、顧客データの取り込み |
| 顛末書 | 相手の分を取り込む | 監督・営業の反映 |
| 専決決裁書・捺印決裁書 | **同期しません**（使わないため） | — |

- タブを行き来しただけで、前の同期から **1分たっていなければ**読みに行きません。読み込み直したときは必ず見に行きます
- 開いたまま相手の変更を今すぐ取り込みたいときは、右上の「共有フォルダー」→**「共有フォルダーと同期」**を押してください（開いている間は自動では見に行きません）
- 右上の表示の意味:

  | 表示 | 意味 | すること |
  | --- | --- | --- |
  | 共有フォルダー: 未設定 | まだフォルダーを選んでいない | 押して「共有フォルダーを選ぶ」 |
  | 共有フォルダー: 未接続 | 前回のフォルダーはあるが、ブラウザの許可が切れている（ブラウザを閉じたあとなど） | 押して「共有フォルダーにつなぐ」→「許可」 |
  | 共有フォルダー: 確認してください | 初回の書き出し・顧客ファイルの入れ替え・読み書きの失敗など、見てほしいことがある | 押して中の案内に従う |
  | 共有フォルダー: 接続済み | つながっている（押すと最終同期の日時が見られます） | なし |

  未設定・未接続・確認してくださいは、定期点検・アフター・顛末書では**黄色で目立たせ**、専決決裁書・捺印決裁書では目立たせません
- ★読み込んだだけでブラウザに許可を尋ねることはありません。尋ねるのはボタンを押したときだけです（許可がまだ生きていれば、尋ねずにそのままつなぎます）

フォルダーの中はこうなります。**Folio が使うものは `_data` の中にまとめ**、直下は業務のフォルダーだけにできます（`.bak` は書き換える前の控えが1世代）:

```
Folio共有/
  _data/                        ← Folio が使うもの。普段は開かなくてよい
    顧客データ.json（＋ .bak）     ← 台帳そのもの。取り込むたびに更新されます
    顧客の手直し.json（＋ .bak）
    学習した書き方_アフター.json（＋ .bak）
    学習した書き方_定期点検.json（＋ .bak）
    （はじめだけ）助っ人クラウド.xlsx・点検保守台帳(ダイテック).xlsx
```

★**共有フォルダーは「データベース」の役割だけ**です。顛末書・専決決裁書・捺印決裁書の PDF は**ここに置きません**。
楽楽精算は人によって見られる伝票が違う（権限が分かれている）ので、取得した PDF を2人で見えるところに置くと、
その区別が意味を失うためです。PDF の保存先は、それぞれの **PC のフォルダー**を選んでください（[顛末書の取得](#顛末書の取得)）。

- **`.data` という名前にもできます。** Folio は `.data` があればそちらを使い、無ければ `_data` を作ります。`.data` は macOS の Finder では隠れますが、**Windows のエクスプローラーでは見えます**（Windows の「隠し」は名前ではなくファイルの属性で、ブラウザからは付けられません）。同期ソフトが `.` で始まる名前を無視することもあるので、**確実なのは `_data`** です。試してうまく同期されなければ、フォルダーの名前を `_data` に変えるだけで動き続けます
- **前に直下に置いていた分は、つないだときに自動で `_data` へ移します**（移し先に同じ名前があれば、直下のものは消さずに残します）

**注意**

- ★**共有フォルダーには顧客データ一式（氏名・住所・電話番号）が載ります。** **見られる人は、そのフォルダーの権限どおり**です。Folio 側では暗号化しません（同じフォルダーに顧客の xlsx を置く運用なので、鍵を増やしても守るものが増えず、鍵を失うと読めなくなるためです）
- Box Drive は既定でファイルを**クラウドにだけ**置きます。共有フォルダーには**「オフラインで利用可能にする」**を付けてください
- **同時に書いても壊れません。** 書く直前にファイルが変わっていないか確かめ、変わっていたら読み直して重ね直します。書き負けても、次の同期で相手の分が戻ります（各端末が全部を持っているため）
- 同期ソフトが作る**競合コピー**（`顧客の手直し (○○の競合コピー).json` など）は Folio は読みません。**消して構いません**
- 書いている途中は、Chrome が `顧客の手直し.json.crswap` のような**一時ファイル**を作ります（書き終わると消えます）。Folio は決まった名前のファイルだけを読むので、残っていても影響はありません。**消して構いません**
- 後勝ちの判定は**各PCの時計**です。2台とも**自動時刻合わせ**にしてください
- 「この端末の顧客データに見つからない手直しが N件」と出ることがあります。**捨てていません**。同じ顧客ファイルを取り込むと結び付きます
- **「学習した書き方を消去」は相手の端末からも消えます**（消した印を共有するため）。顧客データの削除はこの端末だけで、共有フォルダーの手直しは残ります
- ファイルが読めない形になっていたら、Folio は**直さずに止めます**（直した結果を正本として相手にも配ってしまうため）。`.bak` か、ストレージ側の版履歴から戻してください
- 使えるのは Windows / macOS の **Chrome と Edge** だけです（Safari・Firefox・スマートフォンでは使えません）
- つながっていなくても今までどおり使えます。手直しは溜まっていき、次につないだときにまとめて同期されます

## 顛末書の取得

楽楽精算から「最終承認まで進んだ顛末書」の本体PDFと添付書類を取り、1つのPDFに結合して `顛末書№{伝票№の下4桁}.pdf` として**PCのフォルダーに保存**します。

**2026-09-13 に、画面はこの新しい方式だけになりました。** それまでの方式（PCに入れる顛末書取得ツール）は画面から外してありますが、
コードは残してあるので[すぐ戻せます](#今までの方式pcの顛末書取得ツール)。

| | 新しい方式（いまの画面） | 今までの方式（画面からは外した） |
|---|---|---|
| 使うもの | ブラウザ（Chrome / Edge）だけ | PCに入れた顛末書取得ツール（`~/tenmatsu-dl/`、Python） |
| 楽楽精算を操作する場所 | folio のサーバー（Vercel・東京） | そのPC |
| PDFを結合・保存する場所 | このブラウザの中 → 選んだPCのフォルダー | そのPC |
| 記録（`processed.json`） | 保存先フォルダーの `_記録` | ツールのフォルダー |

2つの方式は**記録が別々**です。同じ伝票を二重に取得しないよう、どちらか一方だけを使ってください。今までの方式から移るときは[今までの方式からの移行](#今までの方式からの移行)を参照してください。

### 仕組み（新しい方式）

1. **楽楽精算からの取得は folio のサーバーが行います。** 楽楽精算の画面をサーバーの中のブラウザ（Chromium）で開き、一覧・伝票・承認履歴を読み、本体PDF（印刷）と添付をダウンロードします。1伝票ごとに1回の呼び出しで、進み具合を少しずつ送り返します
2. **PDFの結合と保存はこのブラウザの中で行います。** 受け取ったPDFと画像を1つにまとめ、利用者が選んだPCのフォルダーへ書き込みます
3. **folio のサーバーには、PDFも楽楽精算のパスワードも残りません。** PDFはサーバーを通りますが保存しません。サーバーのログには段階名と件数だけを出します（伝票№・氏名・ファイル名は出しません）。サーバーに置くのは、自動でログインしてよいかの状態（失敗の回数など。秘密は入りません）だけです
4. **楽楽精算のIDとパスワードは、このPCのブラウザに暗号にして登録します**（2026-09-25。[楽楽精算のIDとパスワードの登録](#楽楽精算のidとパスワードの登録)）。取得のときに Folio が自動でログインします。**ログイン状態（暗号化したもの）はこのタブにだけ残す**ので、画面を読み込み直してもログインしたままです（タブやブラウザを閉じると消えます。期限は8時間）。ログインは顛末書・専決決裁書・捺印決裁書に共通です
5. **楽楽精算に対しては検索・閲覧・ダウンロードだけ**を行います（承認・申請・編集・削除や「閉じる」「取下げ」は押しません。コードが参照していないことをテストで見張っています）

### 楽楽精算のIDとパスワードの登録

2026-09-25 から、楽楽精算のログインの小窓は無くなりました。IDとパスワードを**一度だけ登録**すると、取得のときに Folio が自動でログインします（「Folio と楽楽精算のログインが2つあって紛らわしい」という声を受けて）。

- 場所: 右上の人の形のアイコン →「アカウント」→「**楽楽精算のIDとパスワード（取得に使う）**」
- 「**ログインできるか確かめて保存**」を押すと、楽楽精算に1回だけログインして確かめ、**できたときだけ登録します**（打ち間違いは登録しません）
- **置き場所はこのPCのこのブラウザの中だけ**（IndexedDB）です。Folio のサーバーの鍵（`RAKURAKU_SESSION_SECRET` から作る）で暗号にした控えなので、PCの中身だけでは読めません。**社外のクラウド（Upstash など）には置きません**。別のPCで使うときは、そのPCでもう一度登録します
- 控えは Folio のアカウントに結び付けています。同じPCでほかの人が Folio に入っても、その人には見えず、使えません
- **本人だけが自分の分を入れます**（管理者がほかの人の分を入れる・見る道はありません）
- ログインするのは「取得」「いま部門を読み込む」「画面の下見」を押したときだけです（画面を開いただけではしません）
- ★**ロックを避ける決まり**（楽楽精算は続けて失敗するとアカウントがロックされるため。`lib/rakuraku/credential-state.ts`）
  - 自動のログインは、前にログインしたときに成功していたときだけです。**1回でも失敗したら、入れ直して確かめるまで自動ではログインしません**
  - ログインできたかは、着いた画面（「ワークフロー」タブ）で確かめます。確かめられないときも失敗として扱います
  - パスワードを打つ前に「送った」と書き、送ったまま結果が分からないものも失敗として数えます（送る前の失敗は数えません）
  - 失敗のあと60秒は受け付けない・同じアカウントのログインは同時に1つだけ・自動のログインは1日20回まで・「確かめて保存」は3回続けて失敗したら1時間待つ
  - この状態（秘密は入りません）は Folio のアカウントと同じ置き場所（`folio:rk:<ID>`）に置き、どのサーバーからでも同じに守ります
- 楽楽精算のパスワードを変えたときは、自動のログインが1回失敗して止まります。アカウントの画面で「**入れ直す**」を押してください
- `RAKURAKU_SESSION_SECRET` を変えると、全員の登録が読めなくなります（入れ直し）
- 入れる欄は、ブラウザが Folio のパスワードの保存と取り違えないよう、フォームにしていません。Folio のパスワードと同じものが入っていたら、楽楽精算へ送る前に断ります

### 使い方（新しい方式）

画面の上に「①保存先フォルダー ②楽楽精算のIDとパスワードを登録 ③部門を選ぶ ④取得 ⑤一覧で確認」の手順バーが出ます。
押せないときの理由も、ボタンの近くに文字で出ます（[画面の案内](#画面の案内初めて使う人向け)）。

1. **保存先フォルダーを選ぶ** … 「保存先フォルダーを選ぶ」を押して、PDFを置くフォルダー（例: ドキュメントの「顛末書」）を選びます。ブラウザが「編集を許可しますか」と尋ねたら許可してください。Chrome / Edge で「今後も許可」を選ぶと、次からは開くだけでつながります
   - ★**PC のフォルダーを選んでください。Box の共有フォルダー（Folio共有）の中は選べません。** 楽楽精算は人によって見られる伝票が違うので、取得した PDF を共有の場所に置くと、見られないはずの人にも見えてしまいます。共有フォルダーの中（または共有フォルダーを含む上のフォルダー）を選ぶと、Folio ははねて理由を出します。前に選んでいた保存先でも、つなぐときに確かめます
   - ただし見分けられるのは **Folio の共有フォルダーとの位置関係だけ**です。ブラウザからはフォルダーの実際の場所が見えないので、Box の別のフォルダーは見分けられません
2. **楽楽精算のIDとパスワードを登録する**（初めの1回だけ） … 右上の人の形のアイコン →「アカウント」の「**楽楽精算のIDとパスワード**」で、ご自分のログインIDとパスワードを入れて「**ログインできるか確かめて保存**」を押します（[楽楽精算のIDとパスワードの登録](#楽楽精算のidとパスワードの登録)）
   - 顛末書・専決決裁書・捺印決裁書の画面の「楽楽精算」の1行に、登録の状態が出ます（登録が無い・前回ログインできなかったときは、アカウントの画面へのリンクも出ます）
   - **画面を開いただけではログインしません。** ログインするのは「取得」「いま部門を読み込む」「画面の下見」を押したときだけです
3. **部門を選ぶ** … 「取得」を押したとき（このタブでログインしたあとは、画面を開いたとき）に、そのアカウントで選べる部門を**自動で読み込みます**。先に見たいときは「いま部門を読み込む」を押します。部門が選べるのに前に選んだものが無いときは、取得を始めずに止まるので、部門を選んでからもう一度「取得」を押してください。種類ごとに前回の選択を覚えます。**部門の切り替えが無いアカウント**（「閲覧」タブが無い方）では切り替えが画面に無いので、何も出さずにこの手順を通り過ぎ、部門を指定せずに取得します
   - 読み込みに失敗したときは**自動で1回だけやり直します**（2秒待ってから。ログインはやり直しません）。それでも駄目なら、赤い1行と一緒に**「もう一度読み込む」**と**「部門を指定せずに取得する」**の2つのボタンが出ます（**失敗したあとは自動で読み直しません**。押したときだけです）
   - 「部門を指定せずに取得する」は**行き止まりを抜けるための逃げ道**で、普段使う道ではありません。常用が必要なほど失敗が続くなら、読み込めない原因のほうを直します
   - **この逃げ道でも、別の部門の伝票を取ることはありません。** 取得を始めた時点でサーバーが「本当に切り替えが無いか」を確かめ直し、切り替えがあれば**1件も取らずに**止まって、選べる部門を画面に出します（選択肢が読めているときや、選択肢が空のときは、そもそもこのボタンを出しません）
4. **1回に取る件数**（1〜100）を入れて**「顛末書を取得」**を押します。1件あたり10秒ほどかかります

#### 一覧の経路（アカウントによって使える画面が違うとき）

楽楽精算の権限はアカウントによって違い、**ヘッダーに「閲覧」タブが無い人**がいます。その場合は「ワークフロー」タブから取ります。
**「閲覧」タブが無いアカウントは、部門の切り替えも画面に出ません**（所属部門が文字で出るだけです）。Folio はそれを失敗とせず、部門を指定せずに進めます。

- **ログインした時点で「閲覧」タブがあるかを見て、経路を決めます**（2026-09-22）。選ぶ操作は要りません。
  判定は画面の「楽楽精算」の欄に1行で出します（例:「このアカウントには「閲覧」タブが無いので、顛末書は
  「ワークフロー（申請検索）」の一覧から取ります（一覧に出るのは自分が申請した顛末書だけです）」）
- タブが無いアカウントは**申請検索を先に試します**。今までのように閲覧側を1回試して失敗する往復がなくなります
- ★**自部門検索を消さずに後ろへ回します。** 判定が外れていても、申請検索が開けなければ今までどおり切り替わります
- **どの経路で取ったかは必ず画面に出します。** ワークフロー（申請検索）の一覧に出るのは**自分が申請した伝票だけ**なので、部門のほかの人の伝票は出ません
- 前に使えた経路は、暗号化したログイン状態の中に覚えて次から先に試します（ブラウザから一覧のURLを渡すことはできません。渡せるのは経路の名前だけです）。**前に通った経路はタブの判定より優先します**
- 両方の経路とも、一覧の**列の見出し・伝票画面の部品は同じ**であることを実画面で確かめてあります（2026-09-19 の「画面の下見」）。違うのは一覧と伝票画面のURLだけです。URLが効かないときは「ワークフロー → 行為の申請(稟議) → 一覧」とメニューをたどります
- 「一覧の経路」の選択は、**タブの有無を判定できたときは出しません**（選ばなくてよいため）。
  判定を返さない古いサーバーのときだけ、今までどおり固定できます（固定している間は他の経路を試しません）
- 捺印決裁書に紐づく専決決裁書も同じように経路を選びます。申請検索の一覧には自分の申請分しか出ないので、ほかの人が申請した専決決裁書は見つからず、その旨を理由に出して保留にします

#### 画面の下見（開発者に送る情報）

一覧をどの経路でも開けないときは、**楽楽精算の画面の作り**を集めて開発者に送っていただくと直せます。楽楽精算のIDとパスワードを登録したあと、取得の欄にある「**画面の下見**」を開いて「下見を実行」を押すと（ログインしていなければ、押したときに自動でログインします）、文面ができるのでコピーして送ってください（数分かかります）。

- **集めるもの**: メニューの文字、一覧の場所（会社のURLを外した中の場所と `workflowId` など）、一覧の**見出し**、件数表示の形、伝票画面の部品の数と項目の**ラベル**
- **集めないもの**: 伝票の内容・伝票№・氏名・金額・**表の値**・楽楽精算のURL（会社の場所）。3桁以上の数字は伏せます
- **押すもの**: 「ワークフロー」「押印の申請」のタブだけです（申請・承認・データを変える操作はしません。印刷も添付の取得もしません）
- 結果は画面に出るだけで、保存も外部への送信もしません

- 取得中は**「中止」**で、いまの伝票が終わったところで止められます。残りは次の取得で取ります
- **取得中に他の画面へ切り替えても続きます。ブラウザのタブを閉じると止まります**（閉じようとすると確認が出ます）
- 取得中はボタンの下に**「取得の記録」**が出ます（`!` で始まる行は琥珀、`OK 保存` は緑）。記録はこのブラウザの中にだけあり、次の取得を始めるか読み込み直すと消えます。止まったときは、経緯を保存先フォルダーの `_記録/エラー_日時.txt` に残します
- **ログインが切れたとき**は、登録したIDとパスワードでその取得の中で**1回だけ**ログインし直して同じ伝票をやり直します。2回目は止めます（1回の取得でログインするのは、最初の1回と合わせて2回まで）
- 本体PDFが取れなかった伝票は**見送り**（記録しないので次回やり直し）、続けて2件取れなければ止めます
- ほかの人の取得と重なって folio のサーバーが混み合っているときは、少し待ってやり直します
- 一覧を開けない・メニューが出ないときは、まず別の経路（ワークフロー）を試し、それでも開けなければ**試した経路と理由を並べて**出します（そのアカウントの閲覧権限が無い可能性を含め、設定の誤りだけを疑わせないため）
- 一覧の**「ファイルなし」**は、記録はあるが保存先フォルダーに記録の名前のPDFが無い状態です（黙って隠しません）。**PCでPDFの名前を変えただけなら、一覧を読み込み直すと自動でつなぎ直ります**（[PDFの名前を変えたとき](#pdfの名前を変えたとき)）
- 使えるのは **Windows / macOS の Chrome と Edge** です（Safari・Firefox・スマートフォンでは保存先フォルダーを使えません）

### 完了フラグ（実行予算入力済み・クラウド格納済み）

顛末書を取得したあとの手作業――**ダイテックへ実行予算を入力**し、**クラウドへ格納**する――を、一覧の右端のボタンで記録できます。ボタンは状態をそのまま表示し、未完了は白地の「未入力」「未格納」、完了は緑の「✓ 入力済み」「✓ 格納済み」です。

**記録は保存先フォルダーの `_記録/processed.json`（今までの方式ではPCのツールの `processed.json`）に入ります。** ブラウザのデータを消しても残ります（folio のサーバーでは持ちません）。

- ボタンを押すと反対の状態になります。**完了のボタンをもう一度押せば未完了に戻る**ので、押し間違いはそのまま戻せます
- 変更中はその行の2つだけ薄くなって押せなくなります（他の行はそのまま触れます）。応答が返ってから文字と色が変わります
- **取得中でも押せます。** 記録の書き込みは順番待ちで守っているので同時に更新しても失われず、取得の完了後に一覧を取り直して記録の値に揃えます
- **保存できたか確認できなかったときは「変更できませんでした」とは言いません。** 書けているのに失敗に見えることがあり、そこで「保存されていません」と伝えると実行予算を二重に入力させてしまうためです。「一覧を再読み込み」で確かめてください

### 一覧の列

伝票№ / ファイル名 / 物件名 / 申請日 / 申請者 / 支払金額(税込) / 支払先 / 最終承認日 / ページ / 大きさ / 状態 の順で、**右端に「実行予算」「クラウド」のボタンとプレビューの枠**が固定されています（横にスクロールしても常に見えます。楽楽精算のデータ列とは別枠です）。左端の**伝票№とファイル名も固定**なので、横にスクロールしてもどの伝票の行かが分かります。

- 物件名・申請者・支払金額・支払先は**楽楽精算の一覧から読んだ値**、申請日（秒まで）と最終承認日は**伝票画面から読んだ値**です。この項目に対応する前に取得した分は**空欄（`－`）**になります
- 申請日は伝票画面から読めた分は `2026/09/04 17:51:38` と秒まで、一覧からしか読めなかった分は `2026/09/04` と日付だけです。最終承認日は承認履歴の「日付」列でいちばん新しいものです（読めなかった分は空欄になります）
- **見出しもセルも折り返しません。** 表は内容に合わせて横に広がり、枠の中で横スクロールします
- **「取得日時」の列は外しました**（申請日のほうが業務で使うため）。サーバー側には残っているので、必要になれば戻せます
- 件数が増えても見出しが残るよう、表は縦にもスクロールし、**見出しは固定**されます（画面の高さの75%まで）
- **「伝票№」「ファイル名」の見出しを押すと並べ替えられます。** 同じ見出しを押すたびに 既定（取得した順の逆）→ 昇順 → 降順 と変わり、別の見出しを押すとその列の昇順から始まります。**数字は数の大きさで比べる**ので、`顛末書№999.pdf` は `顛末書№1000.pdf` より前に来ます

### 一覧の見せ方

過去分が溜まるので、**やるべき作業が残っている行だけ**が見えるようにしています。

- **既定では完了した行（両方チェック済み）を隠します。** 「完了したものも表示」で出せます
- **絞り込み**で「実行予算が未入力」「クラウド未格納」に絞れます
- 件数は必ず**「表示 N件 / 完了で非表示 N件 / 絞り込みで非表示 N件（全 N件）」**の形で出ます。3つの数は必ず全件に分かれるので、行が消えたのに説明が無い状態にはなりません
- **ファイルが消えている行は、完了していても隠しません。** 件数も絞り込みとは関係なく常に出します
- 絞り込み・切り替え・並べ替えは保存しません（**再読み込みすると既定に戻ります**。他の画面へ切り替えて戻っただけなら、そのままです）

### 監督・営業をお客様の情報に反映

顛末書の「どこで」には `監督：〇〇/営業：〇〇` が入っています。一覧の下の**「監督・営業をお客様の情報に反映」**から、アフターメンテナンスのお客様の情報へ入れられます（**自動では書きません**。何が変わるか見てからボタンを押します）。

- 突き合わせは **PJコード（10桁）の上8桁**です。下2桁は同じ現場の棟の枝番なので落とします。PJは伝票画面の「どこで」のすぐ下の行から読みます
- **お客様の情報に別の値が入っているときは触りません。** 点検保守台帳から取り込んだ営業担当も、手で直した値も上書きしません。**空欄のときだけ**入れます
- **値が食い違うときは反映を見送ります。** 同じ現場の顛末書どうしで監督が違う場合も、同じ現場のお客様どうしで違う場合も、どれが正しいか決められないため書きません（画面に両方の値を出します）
- 反映した値は**「手直し」として保存**されるので、顧客データを取り込み直しても残ります。お客様の情報では「顛末書から反映」と出ます
- PJを読めない顛末書・監督や営業が書かれていない顛末書は**件数で必ず伝えます**（黙って隠しません）
- 顧客データを取り込んでいないブラウザにはこの欄を出しません

定期点検の抽出結果でも、行ごとの**「監督・営業を反映」**と**「監督・営業をまとめて反映」**で、同じ規則（PJ上8桁・空欄のときだけ・食い違いは見送り）で「監督」「営業」の列を埋められます。

### 添付書類

**新しい方式**では、**PDF と画像（JPG / PNG）**を本体と結合します（[PDFでない添付の扱い](#pdfでない添付の扱い2026-09-13-決定)）。

- 画像は A4 の1ページにします。横長の写真は用紙も横向きにし、**スマホ写真の向き（EXIF）を反映**します。画素は元のまま埋め込みます
- **開くのにパスワードが要らない保護のかかったPDF**（スキャナや銀行などが出すもの）は、保護を解いて結合します。本当にパスワードが要るPDFは結合できないので保留にします
- **Excel・Word・PowerPoint・メール**は結合できないので、その顛末書を**保留**にします。手でPDFにして「添付を足す」から入れてください
- 動画・音声（MP4 / MOV / MP3 など）は紙にできないので結合せず飛ばし、一覧に「動画は未結合」と出します
- 取得したファイルの拡張子は**中身で直します**（`.jpg` と表示されていても中身がPNGなら `.png`。ログイン画面などのHTMLが返ってきたらPDFとして扱いません）

**今までの方式**では、Office の添付をPCのアプリ（Windowsのみ）で変換して結合します（Excel は1枚目のシートだけ、メールは本文だけ）。

### 保留（添付を結合できなかったとき）

添付が取れなかった・壊れたPDF・結合できない形式、のいずれかで結合できなかった伝票は**保留**になります。取得はそこで止まらず、残りの伝票は続けて取得されます。

- 本体と結合できた添付だけをまとめたPDFが保存先フォルダーの `_保留` に置かれ、**正式なフォルダにはまだ入りません**
- 一覧の**先頭**に「保留」と出ます。プレビューでその中身（本体＋結合できた添付）を確認できます
- 印（実行予算・クラウド）は**保留中は変えられません**。取得中も操作できません
- 右端の**「添付を足す」**から3つのことができます
  1. **確定する** — 欠けた添付ごとにファイルを選ぶと、**元の順番で**結合し直して正式なフォルダへ保存します。手作業でPDFにしたものでよく、元の添付と名前や形式が違っていて構いません（新しい方式で入れられるのは PDF と画像です）
  2. **欠けたまま確定する** — どうしても手に入らないとき。一覧に**「添付が欠けています」**が残ります
  3. **取り消して次回取り直す** — 保留を消して、次の取得でやり直します（一時的に取れなかっただけならこれが確実です）
- 取得の完了時に **「3件を保存しました (1件は添付を結合できず保留)」** と出ます
- **本体PDFが取れなかったとき**は保留にせず見送ります（次の取得でやり直します）

### 保存とプライバシー

**新しい方式**でこのブラウザに保存するのは、**取得済み一覧の写し・保存先フォルダーの場所・1回に取る件数・選んだ部門・一覧の経路の固定・楽楽精算のIDとパスワードの控え**（登録したときだけ。Folio のサーバーの鍵で暗号にしたもので、ブラウザの中だけでは読めません）です。ログイン状態（暗号化したもの）と部門の選択肢は**このタブにだけ**残し、タブを閉じると消えます。 PDFの実体と記録（`_記録`）は保存先フォルダーにあり、ブラウザにも folio のサーバーにも保存しません。

⚠️ **一覧には伝票№・物件名（施主名を含むことがあります）・申請者・支払先・支払金額が入ります。** 定期点検やアフターの顧客データと同じ扱いが必要です。共有の端末では、使い終わったら画面下部の**「一覧を消去」「保存先フォルダーの登録を消す」**と、アカウントの画面の楽楽精算の「**このPCから消す**」を押してください。一覧を消しても保存先フォルダーの記録は無傷なので、つなぎ直せば戻ります。

一覧は定期点検の「保存データを消去」では**消えません**。

新しい方式で困ったときは、[components/tenmatsu/tenmatsu-page.tsx](components/tenmatsu/tenmatsu-page.tsx) の `SHOW_LOCAL_SERVER` を `true` にするだけで「取得の方法」の選択欄ごと戻ります

選ぶと、PCで動いているツール（`~/tenmatsu-dl/`）に `http://127.0.0.1:8765` で直接つなぎます。取得・結合・保存はすべてそのPCで行い、folio のサーバーは経由しません。

| | 顛末書 | 専決決裁書 |

| ファイル名 | `顛末書№{伝票№の下4桁}.pdf` | `専決決裁書№{伝票№の下4桁}.pdf` |
| 一覧の列 | 物件名 / 申請日 / 申請者 / 支払金額(税込) / 支払先 / 最終承認日 | **表題** / 物件名 / 申請日 / 申請者 / **決裁申請額(税込)** / 支払先 / 最終承認日 |
| 完了の印 | 実行予算・クラウド | **クラウドだけ**（「完了」＝クラウド格納済み） |

- **取得は同時に1つだけです。** 片方を取得している間は、もう片方のタブで取得を始められません
- 添付書類・保存とプライバシーは顛末書と同じです

## 捺印決裁書の取得

取得のやり方は顛末書と同じです。[専決決裁書の取得](#専決決裁書の取得)との違いだけを書きます。

| | 専決決裁書 | 捺印決裁書 |
| --- | --- | --- |
| 保存先 | `Documents\専決決裁書` | `Documents\捺印決裁書` |
| ファイル名 | `専決決裁書№{下4桁}.pdf` | **伝票ごとに変わります**（`御見積書（〇〇）.pdf` / `保険金請求書（〇〇）.pdf`。読み取れなければ `捺印決裁書№{下4桁}.pdf`） |
| 一覧の列 | 表題 / 物件名 / … | **内容** / **専決決裁書№** / 物件名 / 申請日 / 申請者 / 決裁申請額(税込) / 支払先 / 最終承認日 |
| 取得した直後 | 保存先に入る（完成） | **必ず「アップロード待ち」**。書類を入れて確定するまで保存先には入りません |
| 右端のボタン | （印） | **「書類を足す」**（保留中の行） |
| 欠けたまま確定 | できます | **できません**（あとから入れる書類は必ず必要なので、ボタンを出しません） |
| 入れられる書類 | 欠け1つに1ファイル | **何件でも**（ダイアログに一覧で出て、↑↓で並べ替え・「外す」で取り消し） |
| 確定したあと | 変えられません | **右端の「差し替え」**で入れ直せます（同じファイル名で書き直し、格納済みの印は外れます） |
| プレビュー | 確定したPDFを開く | **ダイアログの中に確定後のPDF**が出ます（入れる・外す・並べ替えるたびに変わります） |

- **紐づく専決決裁書と一緒に結合します。** 伝票画面（読めなければ一覧）の「専決決裁書№」で専決決裁書の一覧を探し、その本体と、要件に合う添付
  （決定通知書 / 見積総覧 / 見積： / 写真）だけを取ります。**捺印決裁書そのものの添付は結合しません。** 順番は「入れた書類 → 選ばれた添付 → 専決決裁書の本体 → 捺印決裁書の本体」です
- 紐づけに失敗したときは、**番号が読めない／一覧を開けない／見つからない／本体が取れない**のどれかを取得の記録に出します（本体が取れなくても、選んだ添付は取れるだけ取ります）
- 支払先・決裁申請額は、紐づく専決決裁書の画面から写します
- **決定通知書があるかで並びと名前が変わります。** ある場合は決定通知書だけを挟んで `保険金請求書（〇〇）.pdf`、無い場合は見積総覧・見積・写真を並べて `御見積書（〇〇）.pdf` になります
- **紐づく専決決裁書が見つからないときは「欠け」として残ります。** 別の部門の専決決裁書は一覧に出ないため見つかりません。この場合は書類を入れたあとに「欠けたまま確定する」が選べます
- 物件名は伝票画面の「備考」の `物件名：〇〇` から取り出します
- 取得の最後は「0件を保存しました（N件はアップロード待ち）」と出ます。保存されるのは確定したときです
- **入れる書類は複数でよく、順番も決められます。** 入れたものはダイアログに並び、「↑」「↓」で順番を、「外す」で取り消しができます。
  この並びのままPDFの先頭に入ります
- **入れた書類は、その場でプレビューできます。** ダイアログの右側に「確定後のPDF」が出て、ファイルを入れる・外す・並べ替えるたびに
  その並びに変わります。保存先フォルダーにあるPDF（保留中は結合済みの分、確定後は保存されているPDF）を土台に、入れた書類を差し込んで見せています。
  （今までの方式では、Excel・Word・PowerPoint・メールは確定時にPCで変換するので、プレビューでは案内の1枚で位置だけ示します。）
  「大きく表示」で拡大できます。★この機能より前に取得・確定したものは、プレビューに必要な情報が無いので出せません
  （保留は取り直す、確定済みは一度「差し替え」で組み直すと出るようになります）
- **確定したあとでも「差し替え」で入れ直せます。** 一覧の右端、「プレビュー」の下のボタンです。押すと同じダイアログが開き、
  いま入っている書類が並んだ状態から外す・足す・並べ替えができます。「確定する」を押すまで保存されているPDFは変わりません。
  組み直すと**同じファイル名で書き直し**、中身が変わるので**クラウド格納済みの印は外れます**（一覧に「差し替え済み」と出ます）。
  この機能より前に確定した捺印決裁書は部品が残っていないため差し替えられません（ボタンの説明に理由が出ます）
- 添付書類・保存とプライバシーは顛末書と同じです

## 今までの方式からの移行

今までの方式（PCの顛末書取得ツール）を使っていたPCで、新しい方式へ移る手順です。**ツールと新しい方式を同時に動かさないでください**（記録が別々なので、同じ伝票を二重に取得します）。

1. **ツールを止める** … `顛末書サーバー停止.bat` を実行し、スタートアップに入れていたらショートカットを外します
2. **顛末書タブを開く**（画面は新しい方式だけになっています）
3. **保存先フォルダーに、ツールの保存先と同じフォルダーを選ぶ**（例: ドキュメントの「顛末書」）。PDF・`_保留`・`_部品` はそのまま使えます
4. **今までの記録（`~/tenmatsu-dl/processed.json`）を取り込む**
   - ⚠️ **この取り込みの欄は、移行が済んだので画面から外しています。** また必要になったときは
     [components/tenmatsu/tenmatsu-folder-page.tsx](components/tenmatsu/tenmatsu-folder-page.tsx) の `SHOW_IMPORT` を `true` に戻すと出ます
     （仕組みは消していません。[tenmatsu-import-records.tsx](components/tenmatsu/tenmatsu-import-records.tsx) と [lib/tenmatsu/local/import.ts](lib/tenmatsu/local/import.ts)）
   - 欄を出すと、ファイルを入れてから件数と「PDFがこのフォルダーに何件見つかったか」を確かめて「取り込む」を押す形です
   - 何度取り込んでも同じ伝票が二重になることはありません。取り込む前の記録は `_記録` に控え（`.bak`）として残ります
5. アカウントの画面で楽楽精算のIDとパスワードを登録し、**1回に取る件数を1**にして1件取得し、保存と記録を確かめる

## PDFでない添付の扱い（2026-09-13 決定）

楽楽精算の添付は **PDF と画像がほとんど**で、約700件のうち Word と PowerPoint は0件、Excel は1件、メール (.msg) は1〜2件でした。
それらは添付者の間違いなので、**Office ファイルを自動で PDF にする仕組みは作りません**。

| 形式 | 扱い |
|---|---|
| PDF | そのまま結合する |
| 画像 (jpg / png) | ブラウザの中で A4 の PDF にしてから結合する |
| Excel・Word・PowerPoint・メール | 手で PDF にして「書類を足す」から入れる（既存の仕組み） |
| 動画・音声 | 結合せず飛ばし、その行に「未結合」と出す |

**この結論に至った調べ物**（同じ検討を繰り返さないための記録）

- 会社の Microsoft 365 に通す案（Graph API の `format=pdf`）は実際に動くところまで確認しました。見た目は Office そのものですが、次の問題がありました。
  - Excel の新しいチェックボックス機能が変換されず、`FALSE` や `###` になる
  - 1ファイル 4MB まで（手で入れるときの上限 50MB より狭い）
  - メール (.msg) と画像には対応していない
  - Excel は**ブック全体**が PDF になる（現行の顛末書ツールは先頭シートだけ）
  - フォントが置き換わり、文字がやや太くなる
  - 利用者ごとに Microsoft へのサインインが要る
- Office を使わず Folio 側で変換する案も試しましたが、旧形式 (.doc/.xls/.ppt) を扱えず、見た目も Office とは別物になります。
- どちらも年に数回のためには重すぎるため、**手で PDF にして入れる**ことにしました。


## 処理速度

実測（見本5ペア、2026-08-26）:

| | 変更前 | 変更後 |
| --- | --- | --- |
| 工事区分の判定 | 平均13.6秒 | 平均**2.3秒** |

内訳を測ると、PDFの解析・結合・画像化（ローカル処理）は5ペア合計で約3秒しかかからず、残りはすべてGeminiの応答待ちでした。そこで次の3点で短縮しています。

1. **思考トークンの抑制** — Gemini 3.x系は既定で「思考」してから答えるため遅くなります。`thinkingLevel: MINIMAL` を指定し、判定精度を落とさずに待ち時間を削減（見本5件の工事区分は変更前後どちらも正解5/5）
2. **モデルの選定** — 画像認識は精度が要るので flash系（実測5/5）、要約は速くて品質も十分な flash-lite系。別モデルにすることで無料枠のクォータも分散されます
3. **並列化** — 1ペア内で「要約」と「工事区分」を同時に実行し、さらにペア自体も3件ずつ並列処理（巨大PDFが重なってメモリを圧迫しないよう、同時に扱う合計サイズにも上限あり）

無料枠の上限に当たった場合は、無駄なリトライをせず即座に警告を出して手動入力に切り替わります（待たされません）。

## 要約エンジン（点検内容 / アフター受付内容）

- `GEMINI_API_KEY` を設定すると **Gemini（無料枠）** で自然な要約を生成します（同じキーで工事区分の画像認識も有効になります）。
  1. <https://aistudio.google.com/apikey> で無料のAPIキーを取得（クレジットカード不要）
  2. リポジトリ直下に `.env.local` を作成: `GEMINI_API_KEY=取得したキー`
  3. `npm run dev` を再起動
  - 使用モデルは `.env.local` の `GEMINI_VISION_MODELS`（画像認識）と `GEMINI_SUMMARY_MODELS`（要約）で変更できます。いずれもカンマ区切りで複数指定でき、1日の上限に達したモデルは自動で飛ばされます。「This model ... is no longer available」というエラーが出たら、ここを新しいモデル名に差し替えてください
- キー未設定・API失敗時は自動で**ルールベースの定型要約**にフォールバックします（結果に「定型要約」バッジが付きます）。
- 「この書き方を学習」で覚えた過去の例があれば、今回の入力に近いものを手本としてプロンプトに添えます（[書き方を学習させる](#書き方を学習させる)）。定期点検・アフターメンテナンスのどちらでも使えます。
- 出力は**不具合の事象のみ**です。お客様の要望（補修希望・見積もり希望・無償対応の希望など）と社内の対応方針（弊社継続対応・別日対応・是正不可など）は含めません。
- **事象ごとに①②③を付けて改行**して並べます（1件だけのときは番号なし）。Excelにはセル内改行として貼り付きます。

  ```
  ①1階洋室天井のクロスに凹凸
  ②2階リビング壁のクロスに浮き・隙間
  ③2階階段ササラ仕上げの剥がれ
  ```

  番号付けと改行はサーバー側で組み立てているため、Gemini・ルールベースのどちらでも同じ形式になります（LLMの表記揺れに影響されません）。点検員のメモ（立ち会いや連絡先の申し送りなど不具合でないもの）は番号を付けず末尾に「メモ: …」の行として付きます。
- 備考に要望しか書かれていない項目（例: 電動ブラインドを取り付けたい）は事象が無いため、要約に載りません。工事区分の列や結合PDFには影響しません。
- Geminiへ送信されるのは、**個人情報を伏字化した不具合テキスト**（要約用）、**学習した書き方**（伏せ字済みの入力と本文）、**署名・電話番号を切り落とした点検シート画像**（工事区分用）、**施主名の漢字**（メール文のカナ読み推定用）です。住所・契約番号・電話番号・PDF本体は送信されません。ただし無料枠の送信データはGoogleのサービス改善に利用され得る点にご留意ください。

### アフターメンテナンスの受付内容

コールセンターの受付メモは自由文なので、専用のプロンプトで「不具合の事象だけ」を取り出します（要望・訪問日程・折り返しの約束・挨拶は落とします）。送信前に、選んでいるお客様の氏名・カナ・電話番号・住所・メールアドレスをブラウザ内で伏せ字に置き換えます（顧客レコードが手元にあるので確実に消せます）。「この書き方を学習」で覚えた過去の例があれば、今回のメモに近いものを手本としてプロンプトに添えます（[書き方を学習させる](#書き方を学習させる)）。キー未設定・通信できないときは、ブラウザ内で文を分けて段取りの文を落とすだけの定型処理になります（[lib/summarize/inquiry.ts](lib/summarize/inquiry.ts)）。

## デプロイ（Vercel）

ローカル実行が基本ですが、チームで共有する場合は Vercel にデプロイできます（PDFの解析・結合はブラウザ内で完結するため、サーバー側の構成変更は不要です）。

1. <https://vercel.com> にGitHubアカウントでサインアップし、「Add New… → Project」でこのリポジトリを Import する（フレームワークは Next.js が自動検出されます）
2. 「Environment Variables」に次を設定する
   - `GEMINI_API_KEY` … Gemini APIキー（要約・工事区分の画像認識に使用）
   - Folio のログイン（[一人ずつのアカウント](#ログインfolio-自体のアカウント)）。**必ず設定してください。** 足りないと、本番は全部 503（使えません）になります
     - `KV_REST_API_URL` / `KV_REST_API_TOKEN` … アカウントの置き場所（Upstash Redis）。Vercel の連携（Storage → Upstash for Redis）で **Production だけ**に入れます（★無料プラン・Tokyo・自動で有料に上げない設定）
     - `FOLIO_SESSION_SECRET` … ログインの印に署名する鍵（32文字以上のでたらめな文字列。`openssl rand -base64 48`）。Production に Sensitive で入れます。変えると、全員のログインが切れます
     - `FOLIO_BOOTSTRAP` … 最初の管理者を作る間だけ入れる値（`npm run accounts:bootstrap` が出す。使ったら消す）
   - `APP_SESSION_DAYS` … 任意。ログインを保持する日数（省略時30日）
   - `GEMINI_MODEL` … 任意（省略時 `gemini-3.6-flash`）
   - `RAKURAKU_LOGIN_URL` … 楽楽精算のログイン画面のURL（顛末書・専決決裁書・捺印決裁書の新しい方式に使用）。**会社ごとの情報なのでコードに書かず、Production にだけ入れます**
   - `RAKURAKU_SESSION_SECRET` … 楽楽精算のログイン状態をブラウザに預けるときの暗号鍵（32文字以上のでたらめな文字列）。楽楽精算のIDとパスワードの登録（ブラウザに置く暗号の控え）の鍵も、ここから作ります。変えると、それまでのログイン状態も登録も、すべて無効になります（全員入れ直し）
   - `RESEND_API_KEY` … [問い合わせ](#問い合わせ不具合要望を開発者へ送る)のメールを送る Resend の API キー（権限は Sending access）。無いと問い合わせは送れず、画面の「文面をコピー」だけになります
   - `CONTACT_TO` … 問い合わせの送り先。★独自ドメインが無いので、**Resend のアカウントに登録したメール**にします（それ以外の宛先には送れません）。**コードには書きません**
   - `CONTACT_FROM` … 任意。送り元（省略時 `Folio <onboarding@resend.dev>`。Resend で独自ドメインを確かめたら、そのドメインのアドレスにできます）
   - `RAKURAKU_ALLOW_PREVIEW` … 任意。プレビュー環境でも楽楽精算を操作させたいときだけ `1`（既定では、URLが毎回変わるプレビューが本番の楽楽精算を触らないよう止めています）
3. 「Deploy」を押す。以後は `main` に push するたびに自動で再デプロイされます

注意点:

- 顧客の個人情報を扱うため、Folio のログインの設定（上の3つ）が足りないときは、開いたままにせず全部 503 にします。preview には Redis をつながないので、preview は使えません（本番の楽楽精算を触らせないためでもあります）。本番でアカウントの設定が無いと、楽楽精算の取得も動きません
- **デプロイは GitHub の `main` への push で行います。** 手元から `vercel deploy` する場合、**Vercel の CLI は `.gitignore` を見ません**。個人情報を含む手元のフォルダーは `.vercelignore` で外しています。`.gitignore` に「コミットしない」ものを足したら `.vercelignore` にも足してください
- 楽楽精算を操作する関数には Chromium（`@sparticuz/chromium`）と `playwright-core` を同梱しています（`next.config.ts` の `outputFileTracingIncludes`）。個人情報を含むフォルダーは `outputFileTracingExcludes` で必ず外しています
- 関数は東京（`vercel.json` の `regions: ["hnd1"]`）で動かし、実行時間の上限は300秒です（1伝票＝1回の呼び出し。時間が足りない添付は1つずつ取り直します）
- `playwright-core` と `@sparticuz/chromium` は版を固定し、Chromium のメジャー番号が揃っていることを `tests/rakuraku-versions.test.ts` で見張っています。上げるときは両方を揃えてください

### ログイン（Folio 自体のアカウント）

★これは **Folio を開くためのログイン**です。楽楽精算へは、アカウントの画面で登録したIDとパスワードで、取得のときに Folio が自動でログインします（[楽楽精算のIDとパスワードの登録](#楽楽精算のidとパスワードの登録)。ログインの画面はありません）。

2026-09-24 から、**一人ずつのアカウント**（ログインID＋パスワード）になりました（前は全員で1つの合言葉。前の合言葉のログインは 2026-09-25 に使えなくしました）。

★**1つのアカウントでログインできる端末は1つです。** ほかの端末で同じアカウントにログインすると、前の端末は、次に画面を開いた・読み込み直したときにログイン画面になり、「ほかの端末からログインがあったため、この端末はログアウトしました」と出ます（それまでは右上に名前が出たままです。読み込み直さずに使い続けても、遅くとも5分で切れます）。

| したいこと | どうする |
| --- | --- |
| 自分のパスワードを変える | 右上の人の形のアイコン →「アカウント」→「パスワードを変える」。今のパスワードと新しいパスワード（**8文字以上**。記号や大文字は無くて構いません）を入れます |
| 表示名（右上の名前）を変える | 右上の人の形のアイコン →「アカウント」→「表示名を変える」。右上の名前はすぐ変わります（ログインは切れません）。管理者は「アカウントの管理」の「名前を変える」で、ほかの人の表示名も変えられます |
| 楽楽精算のIDとパスワードを登録する | 右上の人の形のアイコン →「アカウント」→「楽楽精算のIDとパスワード」。**本人だけが自分の分を入れます**（[楽楽精算のIDとパスワードの登録](#楽楽精算のidとパスワードの登録)） |
| パスワードを忘れた | 管理者に**仮のパスワード**を発行してもらいます（メールでの再設定はありません） |
| 人を足す・止める・消す | 管理者だけ。「アカウント」の画面の下の「アカウントの管理」から |

**仮のパスワード**
- 管理者が人を足す・発行し直すと、`xxxx-xxxx-xxxx` の形の仮のパスワードが**1回だけ**出ます。本人に**直接**（口頭か手渡しで）伝えてください。**7日で切れます**
- 大文字・小文字とハイフンは区別しません（電話で伝えても打ち間違えにくくするため）
- 仮のパスワードで入った人は、**自分のパスワードを決めるまでほかの画面を使えません**（右上もログアウトだけになります）

**守り**
- ログインを**5回続けて違える**と、そのIDは15分入れません（同じ場所から30回違えても止まります）。違ったときは「ログインIDかパスワードが違います」とだけ出し、IDがあるかどうかは言いません
- ログイン画面には ID を最初から入れておきません（誰でも開ける画面なので）
- パスワードは**元に戻せない形（scrypt のハッシュ）**だけを Upstash Redis に置きます。置くのは ID・表示名・ハッシュ・状態だけで、**顧客データは置きません**
- ブラウザに残るのは、**署名つきの印**（httpOnly。ID・版・期限。パスワードは入りません）と、右上に名前を出すための表示用の印だけです
- ログインする・パスワードを変える・管理者がアカウントを**止める・仮のパスワードを出す**と、アカウントの**版**が進み、それより前の印は使えなくなります。Folio は**画面を開くたび**と、それ以外でも**5分ごと**に Redis で確かめ直すので、前の端末は次に画面を開いたとき（遅くとも5分で）切れます
- 版は**増えるだけ**です（時計が少しずれたサーバーが書いても戻りません）。印の版のほうが新しいときは、Redis の読みが少し遅れているだけとみなして通します（ログインした直後に切れないように）
- Redis が一時的に落ちても、ログイン中の人は**12時間まで**そのまま使えます。新しいログインは「いま確かめられません」と出ます
- 一度ログインすると、**同じブラウザでは30日間ログインしたまま**です（`APP_SESSION_DAYS` で変えられます）。共有の端末では、作業後に右上の人の形のアイコンから**「Folio からログアウト」**を押してください（このタブの楽楽精算のログインも一緒に忘れます）
- **Basic認証のヘッダー（`curl -u`）は受け付けません**
- 5回の数え方は「照合する前に数える」です（同時にたくさん送られても、上限を超えて照合しません）。同じ場所（IP）の数は**失敗だけ**を数えます（同じ事務所の人がログインしても積もりません）
- ★前の共通の合言葉（`APP_PASSWORD`・`APP_USER`・`FOLIO_LEGACY_UNTIL`）は使いません。前の合言葉のクッキーは「切れた」扱いでログイン画面へ戻します
- ★手元で `APP_PASSWORD` だけを入れた場合は、開いたままにせず止めます（前は `APP_PASSWORD` だけで守れました。今は `FOLIO_ACCOUNTS=file` などの設定が要ります）
- ログイン・ログアウト・パスワード変更・管理は、**別のサイトから送られたものを断ります**（他人を攻撃者の ID で入らせない・勝手にログアウトさせないため）。ログイン後の戻り先も、このアプリの中のパスだけに限ります
- 門番（`proxy.ts` → `lib/account/gate.ts`）だけに頼らず、API のルートも**それぞれ自分でログインを確かめます**

**最初の管理者の作り方（1回だけ・管理者がパスワードを忘れたときも同じ）**

```bash
npm run accounts:bootstrap -- --login <ログインID> --name <右上の名前>
```

1. 出てきた**コード**を控えます（本人だけ）。`FOLIO_BOOTSTRAP` に入れる値（コードのハッシュだけ）も出ます
2. その値を Vercel の Production に Sensitive で入れて redeploy します（`pbpaste | vercel env add FOLIO_BOOTSTRAP production --sensitive`）
3. 本番の `/login` で、ログインIDとコードで入ります → すぐ自分のパスワードを決める画面になります
4. 使い終わったら `FOLIO_BOOTSTRAP` を消します（1回しか使えません。使った印はコードの期限より長く残ります）
- ★その ID が失敗の続きで止まっていても、このコードでは入れます（止められても回復できるように）

**分かっている限り**
- ログインID を知っている人がわざと5回違えると、その人を15分止められます（ID は公開していません。止まっても15分で戻り、管理者は最初の管理者のコードでいつでも入れます）

**手元で動かすとき**
- `FOLIO_ACCOUNTS` を入れなければ、今までどおりログイン無しで動きます（使い方の写真撮りもこれで動きます）
- アカウントの動きを試すときは `FOLIO_ACCOUNTS=file` と架空の `FOLIO_SESSION_SECRET`・`FOLIO_BOOTSTRAP` を入れて `npm run dev` します。アカウントは `.cache/folio-dev-accounts.json`（git にも Vercel にも入りません）に置かれます
- 本番の組み立て（`next build` / `next start`）では、手元のファイルは使いません（設定が足りなければ閉じます）

- APIはリダイレクトせず 401 を返します
- Vercel の無料プラン（Hobby）は**非商用・個人利用が規約上の前提**です。業務利用が続くなら Pro プラン（有料）か、商用利用可の他ホスティングを検討してください
- 要約・画像認識のAPIルートは実行時間上限を60秒（`maxDuration`）に設定し、リトライを含む処理はその内側（要約30秒・画像認識45秒）で必ず打ち切ってフォールバックを返します（楽楽精算のルートは300秒）

## テスト

```bash
npm test
```

定期点検の「どのペアを処理するか」「どの結果を出すか」の規則（ペアIDの引き継ぎ・処理済みの判定・結果の置き換え・表示範囲）は純関数に出してあり（`lib/run-plan.ts`）、`tests/run-plan.test.ts` で固定しています。画面そのもののテスト基盤は無いので、取り違えると被害の大きい規則だけをここに集めています。

顛末書系の新しい方式は、楽楽精算の画面を真似た架空のHTML（`tests/rakuraku/fixtures/`）を手元の Chrome で開いて、一覧・メニュー・部門・伝票・承認履歴・印刷・添付・捺印決裁書の組み立て・**一覧の経路の切り替え**（`tests/rakuraku-routes.test.ts`）を確かめています。**画面の下見**は、見本の表とラベルにわざと目印の文字を入れて、報告にその文字が出ないことを見張っています（`tests/rakuraku-survey.test.ts`）（`tests/rakuraku-*.test.ts`。Chrome が無い環境では飛ばします）。保存・記録・結合・保留は、インメモリのフォルダー（`tests/helpers/fake-fs.ts`）と作り物のサーバー（`tests/helpers/fake-rakuraku-api.ts`）で確かめています（`tests/tenmatsu-local-*.test.ts`）。**楽楽精算のテナントのURL・実在の社員番号がテストに入らないよう `tests/rakuraku-privacy.test.ts` が見張っています**（このリポジトリは公開です）。
今までの方式のローカルサーバーとの通信は、実サーバーを起動せず偽の `fetch` を渡して確かめています（`tests/tenmatsu-client.test.ts`）。一覧の絞り込み・完了の非表示・件数の内訳は純関数に出してあり（`lib/tenmatsu/list-view.ts`）、組み合わせを `tests/tenmatsu-list-view.test.ts` で固定しています。画面の見た目と操作はPC側の**デモモード**（`python server.py --demo`、架空データ・楽楽精算に接続しない）で確認します。

見本PDF（`写真報告書_例/`・`点検報告書_例/`）に対するゴールデンテストを含みます。**見本PDFと期待値フィクスチャ（`tests/fixtures/`）は実在の個人情報を含むためgit管理していません**（`.gitignore` 済み）。これらが無い環境では該当テストは自動でスキップされます（`SAMPLE_PDF_DIR` / `SAMPLE_INSPECTION_DIR` で場所の指定も可能）。

期待値フィクスチャは、抽出結果を目視確認した上で次のように再生成できます:

```bash
npm run dump -- "写真報告書_例/(ファイル名).PDF" --parse > "tests/fixtures/expected/(日付)_(姓).json"
```

## テンプレートが変わったとき

抽出は写真報告書テンプレートの実測座標（`lib/pdf/constants.ts`）に基づきます。レイアウトが変わって抽出できなくなった場合は、

```bash
npm run dump -- "写真報告書のパス.pdf"          # トークンと座標をダンプ
npm run dump -- "写真報告書のパス.pdf" --parse  # パース結果を確認
```

で座標を再計測し、`lib/pdf/constants.ts` を更新してください。未知のレイアウトは誤値を出さず「抽出失敗（赤セル）」として手動入力を促します。

完了報告書の様式（`完了報告書_例/完了報告書（原紙）.xlsx`）が変わったときは、同梱テンプレートを作り直します。

```bash
python3 scripts/build_report_template.py   # 3シートに絞り、個人情報を除いて public/report/ へ
python3 scripts/build_report_fonts.py      # Noto Sans JP を取得・サブセット・gzip
python3 scripts/extract_report_geometry.py # 見本PDFから罫線・ラベル位置を再抽出 (テストの基準)
npm test                                    # tests/report-*.test.ts で崩れを検出
```

見た目を確認するときは架空データでPDFを書き出して見本と比べます。

```bash
npx tsx scripts/dump-report.mts .cache/report --items 1
npx tsx scripts/dump-report.mts .cache/report --items 6
python3 scripts/report_visual_diff.py      # 罫線のずれを数値で確認 (.cache/report/*-side.png)
```

罫線の座標は `lib/report/metrics.ts`、セルの配置は `lib/report/layout/{main-sheet,appendix-sheet}.ts` にあります。
