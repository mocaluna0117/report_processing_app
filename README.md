# Folio（フォリオ）

住宅アフターメンテナンスの報告書処理アプリ。**定期点検**・**アフターメンテナンス**・**顛末書**の3つの画面があり、上部のタブで切り替えます。

## 定期点検

写真報告書と点検報告書のPDFをブラウザにドラッグ&ドロップすると、

1. **写真報告書 → 点検報告書の順に結合したPDF** を作成してダウンロードでき、
2. **写真報告書から抽出した情報を、転記先Excelの列構成そのまま（1報告書=1行）** でコピーでき、
3. **依頼メールの文面**と**完了報告書（Excel / PDF）**もそのまま取り出せる

ローカル実行のWebアプリです。PDFの解析・結合は**すべてブラウザ内**で行われ、ファイルが外部へアップロードされることはありません。

## アフターメンテナンス

お客様から直接お問い合わせがあった補修の受付です（`/after`）。顧客データベースからお客様を選び、コールセンターの受付内容を貼り付けると、Excel転記用の行・メール文・完了報告書を作れます。詳しくは[アフターメンテナンス受付](#アフターメンテナンス受付)を参照してください。

## 顛末書

楽楽精算で最終承認まで進んだ顛末書のPDFを、本体と添付書類を1つに結合して取得します（`/tenmatsu`）。取得したあとの手作業（実行予算の入力・クラウド格納）の進み具合もチェックで記録できます。**このPCで動くローカルサーバー経由**で動くため、取得ツールを入れたPCでだけ使えます。詳しくは[顛末書の取得](#顛末書の取得)を参照してください。

## 使い方

```bash
npm install
npm run dev
```

ブラウザで <http://localhost:3000> を開き、写真報告書・点検報告書のPDFをまとめてドロップしてください。
ファイル名（例: `20260722 【写真報告書】山田　太郎様邸.PDF`）から自動でペアリングされます（手動修正も可能）。

「処理実行」後、結果テーブルの「Excel用にコピー」で全行をまとめてクリップボードへコピーし、Excelに貼り付けます。左端の「行をコピー」ボタンで1行だけコピーすることもできます（行コピーにはヘッダー行は付きません）。

結果テーブル右端のボタンから、行ごとに結合PDF・メール文・**完了報告書（Excel / PDF）**も取り出せます。

不要な報告書は行ごとの**「削除」**で消せます。押すと確認が出て、その報告書の**抽出結果・アップロードしたPDF・ペアリング・結合PDF**がまとめて消えます（取り消せません）。抽出結果だけを消すと次の「処理実行」で戻ってきてしまい、PDFだけ残すと次にファイルを足したときの再ペアリングで復活するため、4つまとめて消しています。処理中は削除ボタンを出しません。

### 再読み込みしても消えません

アップロードしたPDF・ペアリング・抽出結果（結合PDF・メール文のカナ・連絡先を含む）は、**このブラウザの IndexedDB に自動保存**されます。誤ってタブを閉じたり再読み込みしても、開き直せば途中の状態から続けられます。Geminiの無料枠を再消費せずに済むよう、要約や工事区分の判定結果もそのまま復元されます。

- 保存先は**この端末のこのブラウザの中だけ**です。サーバー（Vercelを含む）には送信されません
- 顧客情報（氏名・住所・電話番号・PDF本体）が端末に残るため、**作業が終わったら画面下部の「保存データを消去」**を押してください。共有端末では特に必ず消去してください（1件だけ消すときは結果テーブルの行ごとの「削除」を使います）
- 「保存データを消去」が消すのは**定期点検の分だけ**です。アフターメンテナンスの顧客データ・受付一覧は、それぞれの画面の「顧客データを削除」「受付一覧を消去」で消します（毎回顧客データを取り込み直さずに済むようにしています）
- **学習した書き方**（[書き方を学習させる](#書き方を学習させる)）も「保存データを消去」では消えません。専用の「学習した書き方を消去」か、一覧の「削除」で消します
- 別のブラウザ・シークレットウィンドウ・別端末には引き継がれません
- 保存に失敗した場合（容量不足など）は画面に警告が出ますが、作業自体は続けられます。容量が足りないときは「保存データを消去」で古い分を消してから続けてください（書体を登録している場合は「書体の登録を消す」でも空けられます）（画面下部に保存量の目安が出ます）
- 前回の内容が読み込めなかった場合は、そのタブでは**保存を停止**します（空の状態で保存データを上書きして失わないため）。再読み込みすると復元をやり直せます
- 複数のタブで同時に開くと、後から保存した内容で上書きされます。1つのタブで作業してください

アルファベットと数字は、すべての出力（Excel列・点検内容・結合PDF名）で**半角に正規化**されます（例: `Ａ号棟`→`A号棟`、`ＳＥＣＵＲＥＡ`→`SECUREA`）。

### 事業者の判定ルール

1. 契約番号が **21** 始まり → 必ず「タカマツハウス」
2. 契約番号が **31** 始まり → 必ず「賃貸住宅事業部」
3. 契約番号が **41** 始まり → その他事業者。現場名から判定（【】内の名称、ＳＥＣＵＲＥＡ＝大和ハウス工業）。判定できない・矛盾する場合は空欄＋警告（手動入力）
4. 契約番号で判定できない場合は現場名から: 【】内 → ＳＥＣＵＲＥＡ＝大和ハウス工業 → 「数字.」始まり＝タカマツハウス → その他＝賃貸住宅事業部

契約番号の規則と現場名からの推定が食い違う場合は、値に警告（黄セル）が付きます。ルールは [lib/pdf/parse-photo-report.ts](lib/pdf/parse-photo-report.ts) の `resolveDeveloper` にまとまっています。

### 工事区分の判定（点検報告書の画像認識）

点検報告書は手書きのチェックシートを撮影したPDFなので、テキスト層では読めません。そのため **Gemini（画像認識）** で「不具合」列の「有」に丸が付いた行を判定し、その項目名を工事区分（[lib/work-categories.ts](lib/work-categories.ts) の30区分）に対応付けます。

- 工事区分が複数ある報告書は、**工事区分の数だけ行を展開**して出力します（物件数の★は先頭の行だけ、他の列は同じ値）。0件なら工事区分が空欄の1行です
- 結果テーブルでは同じ報告書の行がまとめて表示され、プルダウンで工事区分の修正・追加（＋）・削除（✕）ができます。画像認識が自信なしと判定したものは黄色で表示されます

#### 点検内容は工事区分ごとに分かれます

工事区分が2件以上ある報告書では、「点検内容」が**行ごとの入力欄**になり、区分ごとに別の内容を書けます（貼り付けたときも行ごとの内容が入ります）。切り替えのボタンはなく、**工事区分の数で自動的に決まります**。

- 中身は**事象の文に出てくる工事区分名・別名で自動的に振り分け**られます（「クロスに凹凸」→ クロスの行、「換気扇から異音」→ 換気システムの行）。区分名が出てこない事象は「その他」の行、無ければ先頭の行に入るので、必要なら欄をまたいで書き直してください
- 振り分けが走るのは**処理した直後**と**工事区分を1件から2件に増やしたとき**です。区分を選び直しても本文は動かしません（手で直した内容を壊さないため）
- 点検員メモ（「メモ: …」）と「不具合の指摘なし」の定型文は先頭の行にだけ付きます
- **メール文・完了報告書・書き方の学習は全行をまとめた内容**になります（区分の順に並べ直して①②③を振り直します）。完了報告書ダイアログの指示内容は**工事区分ごとのグループ**で並び（番号は通し）、直した項目はその区分の行にだけ書き戻されます
- 工事区分を消して1件以下になると、残った行の内容が共通の欄にまとまります（消した行の内容は残りません。本文が入っている行を消すときは確認が出ます）
- 「処置」欄は分かれても報告書ごとに1つです（Excelに貼ってから記入する欄のため）
- Geminiへ送る画像は、**下部の署名・電話番号ブロックを切り落としたチェックシート部分のみ**です（顧客契約番号・点検員名・手書きメモは写り込みます）
- `GEMINI_API_KEY` 未設定時は判定を行わず、警告を出して手動選択に任せます

> **無料枠の上限について**: Geminiの無料枠は**モデル単位で1日20リクエスト**です（実測値。公式はダッシュボード参照方式に変わり数値を非公開）。そこで本アプリは**実測で正解5/5だったモデルを順に使い、上限に達したら自動で次のモデルへ切り替えます**。既定のモデル列は次の3つで、合わせて**1日あたり約60件**まで自動判定できます。
>
> | 順番 | モデル | 実測 | 速度 |
> | --- | --- | --- | --- |
> | 1 | `gemini-3.5-flash` (MINIMAL思考) | 5/5 正解 | 約2.3秒 |
> | 2 | `gemini-3-flash-preview` (MINIMAL思考) | 5/5 正解 | 約2.3秒 |
> | 3 | `gemini-3.6-flash` (既定の思考) | 5/5 正解 | 約13.6秒 |
>
> 切り替えが起きた場合は「〇〇(1日の上限に到達) のため別モデルで判定しました」と警告に出ます。判定に使われたモデル名は、結果テーブルの「工事区分 N件」バッジにマウスを乗せると確認できます。すべて上限に達した場合は待たずに警告を出し、手動選択に切り替わります（他の列の抽出・結合PDF・要約は影響を受けません）。
>
> モデル列は `.env.local` の `GEMINI_VISION_MODELS` で変更できます（カンマ区切り、`モデル名:思考レベル` 形式。`default` でモデル既定の思考）。件数がこれを超える場合は Google AI Studio で従量課金を有効にしてください（公式のトークン計算式からの試算で1枚あたり0.1円未満）。
>
> なお lite系モデルは1日の上限が緩いものの、手書きの丸を正しく読めず精度が大きく落ちる（実測3/5）ため画像認識には使いません。要約には lite系を使っています。

### 引渡日を顧客データへ反映

写真報告書の引渡日は、アフターメンテナンスの顧客データ（xlsx由来）の引渡日より確かです。そこで**処理実行が終わった時点で、照合できた顧客の引渡日を報告書の値で自動的に更新**し、結果テーブルの下に何を更新したかを表示します。顧客データを取り込んでいないブラウザでは何も出ません。

- 照合はまず **PJ（契約番号）**で探し、点検保守台帳（DX）はPJの一致で確定、助っ人クラウドは**氏名か住所の裏取りが取れたときだけ**確定とします（助っ人クラウドのPJは管理IDからの変換なので別人と衝突しうるため）。PJで見つからない場合は**氏名と住所の2つが揃ったとき**に候補として出します
- 物件名の**棟・区画の記号が食い違う顧客には結び付けません**（A号棟とB号棟）。住所は「3丁目14番10号」＝「3-14-10」、台帳側に建物名や枝番が付いただけのものも同じ住所として扱います
- **自動更新は「照合が確実」なものだけ**です。次のものは自動では書かず、行ごとの「更新」ボタンで反映します
  - 照合が確実でない（PJのみ一致・氏名と住所だけの一致）
  - 報告書の引渡日が要確認（黄セル）
  - 顧客データ側で引渡日を手直し済み
- 自動更新した行は**「元に戻す」**で取り込み値に戻せます。「残りをすべて更新」で要確認の分もまとめて反映できます
- 反映した引渡日は**「手直し」として保存**されるので、顧客データを取り込み直しても残ります。顧客カードには「定期点検の報告書から更新」と出て、「取り込んだ内容に戻す」で取り消せます
- 顧客データはこのブラウザの IndexedDB にあるため、**顧客データを取り込んだ端末・ブラウザで処理**してください

### メール文のコピー

結果テーブル右端の「メール文」ボタンで、依頼メールに貼れるテキストを確認・コピーできます。

```text
【物件情報】
引渡日：2025/09/26
物件名：（物件名称）
施主名：山田　太郎（ヤマダ　タロウ）様
住所：（住所）
連絡先：090-0000-1234

【依頼内容】
①…
②…
```

- 物件名・施主名・住所・依頼内容は結果テーブルの現在値から作られるので、テーブルで直せばメール文にも反映されます。引渡日はメール文だけゼロ埋め（yyyy/mm/dd）です
- **施主名のカナは Gemini の推定です。** PDFに読みは無いため、漢字の氏名だけを Gemini に送って推定しています。読みが複数ありえる名前（裕子＝ユウコ／ヒロコ 等）や外国人名は黄色で候補を示すので、確認画面で必ず目視・修正してください（修正した値は保持されます）。キー未設定時は空欄になり、手入力します
- 連絡先は点検報告書のテキスト層（下部の電話番号欄）から抽出します。②の番号がある場合は「連絡先①：番号（続柄）」「連絡先②：番号（続柄）」の2行、①のみなら「連絡先：番号」になります。電話番号はブラウザ内でのみ扱い、外部には送信しません

### 完了報告書の作成（Excel / PDF）

**見出しの各欄（PJコード・引渡日・物件名・施主名・施主名のカナ・住所・連絡先①②・受付日・受付者）はモーダル内で直接編集できます。** 直した内容は結果テーブルの該当セル（連絡先はメール文と共通の値）にも書き戻されるので、テーブルに戻って直す必要はありません。受付者だけは完了報告書だけの値で、空欄にすると既定の「木村美恵子」で出力します（結果テーブルの「受付者」列とは別です）。

指示内容もモーダル内で直接編集でき（項目の追加・削除も可能）、直した内容は結果テーブルの「点検内容」（アフターメンテナンス受付では「アフター受付内容」）とメール文にも反映されます。工事区分が2件以上ある報告書では**工事区分ごとのグループ**で並び（番号は区分をまたいで通し）、直した項目はその区分の行にだけ書き戻されます。

結果テーブル右端の「完了報告書」ボタンで、社内様式の完了報告書を **Excel（.xlsx）と PDF** でダウンロードできます。どちらも保存名は `完了報告書（原紙）.xlsx` / `完了報告書（原紙）.pdf` 固定です。

| 欄 | 入る値 |
| --- | --- |
| PJコード / 引渡日 / 物件名 / 住所 / 受付日 | 結果テーブルの現在値（テーブルで直せば反映されます） |
| 施主名 | `姓　名（セイ　メイ）` ＋ Excelの表示形式が付ける「 様」。カナが空なら括弧ごと省きます |
| 連絡先①② | 点検報告書から抽出した電話番号（メール文と同じ） |
| 受付者 | 既定は「木村美恵子」。ダイアログの「受付者」欄で報告書ごとに変えられます |
| 立会 / 受付項目 | ダイアログのチェックボックスで選べます（既定は**点検のみ**）。変更はリロード後も保持されます |
| 指示内容 | 点検内容の各項目。**5件までは本紙に №①〜⑤ ＋ 本文**、**6件以上は本紙を「別紙参照」の1行だけにして、全件を別紙に記載**します |
| 作業内容・是正内容 以降 | 空欄のまま（作業内容の№だけ本紙の数式で指示内容と揃います） |

- **Excel**: 同梱テンプレート `public/report/completion-report.xlsx` の「入力シート」「作業報告書　兼　完了報告書」「別紙」の3シートを保ったまま、必要なセルだけ書き換えます。本紙は入力シートを参照する数式のままなので、Excelで入力シートを直せば本紙も追従します（数式のキャッシュ値も書いているので、再計算しないビューアでも値が見えます）
- **PDF**: 見本PDFと同じ体裁をブラウザ内で描き起こしています（A4縦・罫線・チェックボックス・別紙ページ）。別紙は1ページ12件で、13件以上は別紙を複数ページに分けます（Excelの別紙シートは12件までなので、その場合は警告が出ます）
- 生成はすべてブラウザ内で、テンプレートとフォントは静的ファイルの取得だけです（個人情報はサーバーへ送られません）。フォントは HarfBuzz（hb-subset）で **その報告書に出てくる文字だけに絞って**から埋め込むので、PDFは数十KBです

#### PDFの書体（游ゴシックにしたい場合）

既定は **Noto Sans JP（OFL-1.1、同梱）** です。見本と同じ **游ゴシック**にしたい場合は、完了報告書ダイアログの「PDFの書体」から**この端末に入っている游ゴシックを登録**できます。

- 游ゴシックは Windows / Microsoft Office に付属する書体で **再配布はできない**ため同梱していません。一方でフォント自身の埋め込み設定は `fsType = Editable`（埋め込み可）で、ライセンス表記も「このフォントに含まれる埋め込み制限の範囲で文書に埋め込んでよい」となっています。**ライセンスを持つ端末で自分の文書に埋め込むのは許可**されている、という前提の機能です（Excelの「PDFとして保存」と同じ扱い）
- 登録の仕方は2通り。Chrome / Edge なら「端末の游ゴシックを使う」（フォントへのアクセス許可を1回聞かれます）。他のブラウザではフォントファイルを選びます
  - Mac（Office同梱）: `/Applications/Microsoft Word.app/Contents/Resources/DFonts/YuGothR.ttc` と `YuGothB.ttc`
  - Windows: `C:\Windows\Fonts\YuGothR.ttc` と `YuGothB.ttc`
  - `.ttc`（複数書体入り）から適切な書体を自動で選びます（Yu Gothic UI などの派生は避けます）
- **一度登録すれば以後は自動的にその書体で作られます**（「保存データを消去」しても書体の登録は残ります。顧客データではなく設定として扱うため）
- 登録したフォントは**この端末の IndexedDB にだけ**保存され、外部には送信されません（約27MB）。画面下部の保存欄に内訳が出て、**「書体の登録を消す」**でいつでも消せます（完了報告書ダイアログの「同梱の書体に戻す」でも同じ）
- フォントに無い文字は「〓」に置き換えて警告します

## アフターメンテナンス受付

お客様がコールセンター等へ直接お問い合わせして発生する補修の受付です。画面上部の「アフターメンテナンス」タブ（`/after`）から使います。

### 1. 顧客データを取り込む

顧客情報の xlsx / csv をドロップすると、次の2形式を**自動で判定**して取り込みます。

| 形式 | 位置づけ | 取り込み方 |
| --- | --- | --- |
| 助っ人クラウド 顧客情報 | 旧システム。今後この形式でデータが増えることはない | **入れ替え**（同じ形式のデータを丸ごと差し替える） |
| 点検保守台帳（DX）顧客情報 | 今後の正。同じ列のファイルを追加していく | **PJ（物件番号）で追加・更新**（載っていない顧客は消さない） |

取り込まない行は、理由と行番号がまとめて表示されます（「物件名が×使用禁止×」「物件番号の末尾が01以外」「技術行」「内容が同じ行」「空行」）。

助っ人クラウドの**管理IDが「DX」の行**（点検保守台帳へ移した印）は、**落とさずに取り込みます**。台帳にも載っていれば下記の重複解消が消すので取りこぼしません。逆にここで落とすと、**台帳側が「×使用禁止×」だった顧客がどちらのファイルからも消えます**（実データに1件ありました）。

主な変換:

- **PJ**: 助っ人クラウドは管理IDから変換（`1234-5`→`1012340101`、`123-4`→`1101230101`、`12-3`→`1100120101`、`1-2`→`1100010101`、`B12-3`→`2100120301`）。**規則に当てはまらない管理ID（`DX`・物件名が入っているものなど）はPJを空欄にして「要確認」**にします（実データでは取り込み後1034件が該当）。点検保守台帳は物件番号をそのまま使います（`(BS)`付きは数字部分）
- **事業者**: 点検保守台帳は物件番号の先頭2桁から（10・11＝EU / 21＝タカマツハウス / 31＝賃貸住宅事業部 / 51＝倉庫事業）。41始まりは物件名から（SECUREA・セキュレア＝大和ハウス工業 / リーフィア＝小田急不動産 / 三鷹市下連雀＝コスモスイニシア / 北加瀬1丁目の家・鹿島田の家＝福禄不動産）。**判定できないものは空欄＋要確認**にし、画面で直します。助っ人クラウドは担当支店をそのまま（「エンドユーザー」→「EU」）
- **物件名称**: 「(仮称)」「新築工事」「分譲住宅」「（全N区画）」「（N区画）」「（BS）」「第N期M区画」を除き、半角カナ（ｾｷｭﾚｱ）を全角にします
- **氏名・カナ**: 姓名の間を全角スペースに揃え、カナはカタカナに直します（法人名は空白をそのままにします）。**連名は要確認にしません** — 「サトウ　ハナコ・サトウ　ジロウ」の「・」区切りに加え、「サワダ　イサム（タチバナ　ミキコ）」のように2人目を括弧で添える書き方（氏名欄が「澤田　敢（橘　幹子）」のとき）も正しい書き方として扱います。括弧は全角に、読点・半角中黒は「・」にそろえます
- **連絡先**: 「090-0000-0000（奥様）」のような続柄付きの番号を、番号と続柄に分けます。助っ人クラウドは携帯→固定、点検保守台帳は TEL1→TEL2 の順です
- **住所**: 点検保守台帳は「所在地住居表示」に「建物名」を全角スペースで続けます
- **引渡日**: 点検保守台帳は **備考の「エンド引渡日：2025/3/10」→「築年月日」列** の順に見ます（どちらも無ければ空欄）。備考にはメール文の控えなど別の「引渡日：」も入るため、「エンド引渡日」の見出しだけを拾います。日付は `2025/3/10`・`2025-3-10`・`2025年3月10日`・`20250310`・全角数字・時刻付き・和暦（`令和7年3月10日`）・**Excelの日付書式のセル**のいずれでも読めます。エンド引渡日は**年と月の区切りが打ち間違いで抜けていても読みます**（`202310/30`→`2023/10/30`。月と日の区切りが残っていれば日付の切れ目は一意に決まるため）。読めない値は空欄にして、その値を要確認に出します

**要確認**の顧客は「要確認 N件」ボタンで絞り込めます。画面で直した内容は**取り込み値とは別に保存**されるので、同じファイルを取り込み直しても消えません（「取り込んだ内容に戻す」で戻せます）。

#### 両方に載っている顧客（点検保守台帳が正）

同じ物件が両方のファイルにあると重複して出てしまうため、取り込みのたびに全件を突き合わせ、**点検保守台帳（DX）を正として助っ人クラウド側を消します**。判定は `lib/after/dedup.ts`（純関数）です。

- 手がかりは **PJ・氏名・住所・物件名** の4つで、**2つ以上そろって初めて**同じ物件とみなします。1つだけの一致は当てになりません（助っ人クラウドの管理ID→PJ変換は規則が不完全で、実データでは**別人のPJと5組衝突**していました。「架空が丘4丁目A号棟」のように事業者違いで物件名だけ同じ例もあります）
- 照合では表記ゆれを吸収します。住所は「3丁目14番10号」＝「3-14-10」、台帳側に**建物名や枝番が付いただけ**（`…2-12-9SORA`、`44-1` と `44-1-3`）も同じ住所として扱います。氏名は法人格・肩書き・括弧書き、物件名は括弧書き・【】・「新築工事/新築計画」を落とします
- **住所がはっきり違うものは、他がそろっていても消しません**（同じ施主が別の場所に建てた2棟目がありました）。消さずに要確認として画面に出します
- **棟・区画の記号が食い違うものは結び付けません**（「A棟」と「B号棟」→ 記号 A / B で別の建物）。同じ敷地の別棟は施主も住所も同じなので、これが唯一の見分け方です。書き方の違い（`C棟` / `C号棟` / `A区画` / `5号地`）は吸収します
- 棟の記号が無くて相手を1つに絞れないときは、助っ人クラウド側の件数が台帳側**以下**なら全部が台帳に載っているとみなして消し、**多い場合は台帳に無い棟が混じっている**ので消しません
- 補完は**相手が1件に定まったときだけ**行います（どの棟の引渡日か取り違えないため）
- 消すときは、**台帳が空欄の項目だけ**を助っ人クラウドから補います（顧客カードに「助っ人クラウドから補完」と出ます）。台帳に値がある項目は常に台帳が勝ち、あとで台帳に値が入れば補完は外れます。実データでは台帳317件のうち123件が引渡日を持たず、**重複40件はすべて助っ人クラウドの引渡日で埋まりました**
- どちらを先に取り込んでも、何度取り込み直しても最終状態は同じになります

実データ（助っ人クラウド3671件 / 台帳317件）では **40件**が重複として消え、**1件**が要確認として残りました（合計3948件）。

### 2. 受付を登録する

お客様を検索（氏名・カナ・PJ・物件名・住所・電話番号。ひらがな/カタカナ・ハイフンの有無は区別しません）して選び、コールセンターの受付内容を貼り付けて「受付を登録」を押します。

- 受付内容は**不具合の事象**に要約されます（訪問日程・折り返しの約束・挨拶は落とします）。不具合が書かれていない依頼（「網戸を追加したい」など）は、**依頼の内容がそのまま入ります**（空欄で登録されないように）
- Gemini APIへ送るのは、**選んでいるお客様の氏名・カナ・電話番号・住所・メールアドレスを伏せ字にした受付内容だけ**です。キー未設定・通信できないときはブラウザ内の定型処理に切り替わります
- 段取りの連絡だけで内容が取り出せなかった場合は空欄になり、受付欄に理由が出ます（受付一覧の「アフター受付内容」に直接入力してください）

#### 書き方を学習させる

要約をそのまま使うことは少なく、たいてい少し書き直すことになります。**「この書き方を学習」**を押すと、その1件を（伏せ字にした入力 → 直したあとの本文）の組で覚え、**次回以降の要約で手本として Gemini に送ります**（文体・語尾・1件にまとめる粒度・用語がその書き方に寄ります）。

**定期点検とアフターメンテナンスの両方にあります。** 入力の形とプロンプトが違うので、手本の一覧は画面ごとに別々です。

| 画面 | ボタンの場所 | 覚える組 |
| --- | --- | --- |
| 定期点検 | 結果テーブルの行 | 不具合項目（場所・部位・症状・備考） → 点検内容 |
| アフターメンテナンス | 受付一覧の行 | 受付メモ → アフター受付内容 |

- ボタンは「この書き方を学習」→ 押すと「学習済み ✓」、そのあと本文を直すと「再学習」になります。本文が空欄のときは押せません。定期点検では、この機能を入れる前に処理した報告書（不具合項目の文を持たない行）も押せません
- 送るのは**今回の入力に近いものから最大8件**です（合計の文字数にも上限があるので、待ち時間はほとんど変わりません）
- 保存・送信するのは**伏せ字にした本文だけ**です（氏名・カナ・電話番号・住所・メールアドレスは、保存時と送信時にそれぞれ伏せ字にします）。表の上の「一覧・消去」で、保存されている本文をそのまま確認・削除できます
- 保存は各画面200件までで、超えると古いものから落ちます
- `GEMINI_API_KEY` 未設定時の定型要約には使われません（手本は Gemini へのプロンプトに載せるものなので）

### 3. 受付一覧から取り出す

定期点検と同じ結果テーブルですが、次の点が違います。

- **貼り付けは備考欄を除いた23列**（備考欄は定期点検の「点検報告書作成」用の欄のため）
- **受付種別・受付者はプルダウン**。受付種別の既定は未選択で、未選択のままコピーしようとすると確認が出ます。受付者の既定は「木村」
- **結合PDFはありません**（写真報告書・点検報告書が無いため）。行の「削除」で受付を取り消せます
- **メール文**の連絡先・カナは顧客データの値を使います
- **完了報告書**は受付項目の既定が「アフター」、別紙のタイトルが「アフターメンテナンス是正項目」になります（受付者欄の既定は定期点検と同じ「木村美恵子」で、ダイアログで直せます）
- **物件数には定期点検と同じく★**が入ります（工事区分を足して複数行に分かれても先頭の行だけ）

### 保存とプライバシー

顧客データ（数千件の氏名・住所・電話番号）と受付一覧は、**この端末のブラウザ内（IndexedDB）にだけ**保存されます。

- 定期点検の「保存データを消去」では**消えません**。毎回取り込み直さずに済むようにしているためです
- 消したいときは、この画面の**「顧客データを削除」「受付一覧を消去」**を使ってください。共有端末では作業後に必ず消してください
- 受付内容の原文もこの端末にだけ保存されます（要約のために送るのは伏せ字にした本文だけです）
- **学習した書き方**（伏せ字済みの入力と直した本文）も同じブラウザ内に保存されます。定期点検とアフターで別々の一覧です。設定として扱うため「受付一覧を消去」「保存データを消去」では消えず、**「学習した書き方を消去」**または一覧の「削除」で消します。別の端末・ブラウザには引き継がれないので、移すときは一覧の**「JSONで書き出す」「JSONを読み込む」**を使ってください

## 顛末書の取得

楽楽精算から「最終承認まで進んだ顛末書」の本体PDFと添付書類をダウンロードし、1つのPDFに結合して `顛末書No.{伝票No.の下4桁}.pdf` としてPCに保存します。取得そのものを行うのは別のツール（`~/tenmatsu-dl/`、Python + Playwright）で、folioはその**実行ボタンと進捗・取得済み一覧・プレビュー**を担当します。

### 仕組み（ここが大事）

ブラウザが `http://127.0.0.1:8765` を**直接**叩きます。**folioのサーバー（Vercel）は経由しません。** 施主の氏名・住所を含むPDFがサーバーへ送られることはありません。

`https://` のページから `http://` を呼べるのは、ループバックアドレスが W3C Secure Contexts 仕様で "potentially trustworthy" とされ、混在コンテンツとしてブロックされないためです。

### 一度だけの準備

1. `~/tenmatsu-dl/config.json` の `server.allowed_origins` に **folioのURL**（例 `https://folio-xxxx.vercel.app`）を追加する。追加したらサーバーを起動し直す
2. `顛末書サーバー起動.bat` をダブルクリックする（黒い画面が出たままになります。閉じると止まります）
3. folioの「顛末書」タブで**「接続する」**を押し、黒い画面に表示されている**トークンを貼り付けて「登録」**する

トークンはこのブラウザ内にだけ保存されます。サーバーを入れ直すと変わるので、そのときは「登録し直す」を押してください。

### ブラウザの許可（初回1回）

Chrome 142 / Edge 143（2025-10）以降、公開HTTPSのページから `127.0.0.1` へアクセスすると**「このデバイス上のアプリへのアクセスを許可しますか」**というプロンプトが出ます。**「許可」**を選んでください。オリジン単位で記憶され、あとから `edge://settings/content` / `chrome://settings/content` のサイトの権限で直せます。

プロンプトを見過ごして拒否が残らないよう、**最初の通信は必ず「接続する」を押したときに起こる**ようにしてあります（画面を開いただけでは何も通信しません）。`npm run dev`（`localhost:3000`）ではプロンプトは出ません。

### 使い方

「顛末書を取得」を押すとボタンが `処理中… (3/10 完了)` に変わり、完了すると一覧が更新されます。

- **楽楽精算の画面がPC上で開き、ログインを求められることがあります**（その画面で入力してください）。数分かかることがあります
- このタブを閉じても**取得はPC側で続きます**。戻ってきたら「接続する」で進行中の処理に合流できます
- **1回に取る件数を指定できます**（1〜100）。初期値と上下限はPCのサーバーから受け取り、**指定した件数はこのブラウザに覚えます**。範囲外を入れたときはサーバーが断るので、そのメッセージのとおりに直してください（folio では黙って丸めません）
- 見送った分があると**「残りN件は次回実行してください」**と出るので、もう一度押してください
- 一覧の**「ファイルなし」**は、記録はあるがPCの保存先からPDFが消えている状態です。行を薄く出してプレビューを押せなくしています（黙って隠しません）
- **デモモード**（PC側で `python server.py --demo`）で繋いだときは、画面に**「デモモード（架空データ）」**と出ます。楽楽精算には接続しません

### 完了フラグ（実行予算入力済み・クラウド格納済み）

顛末書を取得したあとの手作業――**ダイテックへ実行予算を入力**し、**クラウドへ格納**する――を、一覧のチェックで記録できます。

**記録はPCの `processed.json` に入ります。** ブラウザのデータを消しても、別の端末から見ても残ります（folio 側では持ちません）。

- チェックは**入れる・外すの両方**できます。押し間違いはそのまま戻せます
- 変更中はその行の2つだけ操作できなくなります（他の行はそのまま触れます）
- **保存できたか確認できなかったときは「変更できませんでした」とは言いません。** 通信が切れた場合、PC側では書けているのに失敗に見えることがあり、そこで「保存されていません」と伝えると実行予算を二重に入力させてしまうためです。「一覧を再読み込み」で確かめてください
- PC側のツールが古いとチェック欄は「－」になります（`~/tenmatsu-dl/` を更新してください）

### 一覧の見せ方

過去分が溜まるので、**やるべき作業が残っている行だけ**が見えるようにしています。

- **既定では完了した行（両方チェック済み）を隠します。** 「完了したものも表示」で出せます
- **絞り込み**で「実行予算が未入力」「クラウド未格納」に絞れます
- 件数は必ず**「表示 N件 / 完了で非表示 N件 / 絞り込みで非表示 N件（全 N件）」**の形で出ます。3つの数は必ず全件に分かれるので、行が消えたのに説明が無い状態にはなりません
- **ファイルが消えている行は、完了していても隠しません。** 件数も絞り込みとは関係なく常に出します
- 絞り込みと切り替えは保存しません（開くたびに既定に戻ります）

### 添付書類

対応形式は **PDF / JPG / JPEG / PNG / XLSX / XLS / XLSM** です。ExcelはPCの1枚目のシートをPDFに変換して結合します。

**変換できるのはExcel（デスクトップ版）が入ったWindowsだけです。** 変換できないときは、サーバーは**黙って飛ばさずにその顛末書の取得を中止**します（添付が欠けたPDFを正式書類として作らないため）。そのときのメッセージは画面にそのまま全文出るので、指示のとおり手作業でPDFにしてから結合してください。

### 繋がらないとき

原因は次の3つのどれかです。**ブラウザ側からはどれなのか判別できません**（許可していないオリジンへの応答にはCORSヘッダーが付かないため、通信エラーと区別が付きません）。3つとも確認してください。

1. サーバーが起動していない（`顛末書サーバー起動.bat`）
2. ブラウザの「このデバイス上のアプリ」の許可が出ていない
3. このページのURLが `allowed_origins` に入っていない（追加したらサーバーを起動し直す）

### 保存とプライバシー

このブラウザに保存されるのは**取得済み一覧（伝票No.・ファイル名・取得日時・チェックの状態）とトークン・1回に取る件数だけ**です。**PDFの実体はPCの保存先フォルダにあり、ブラウザにもVercelにも保存されません。**

一覧は定期点検の「保存データを消去」では**消えません**。画面下部の**「一覧を消去」「トークンの登録を消す」**で消せます。

**「一覧を消去」で消えるのは、この画面が持っている一覧の写しだけです。** PCの記録・PDF・完了フラグは無傷なので、**「一覧を再読み込み」か「つなぎ直す」で元に戻ります**（消した直後に勝手に戻ることはありません）。

### 制限

- 動作を確認しているのは Chrome / Edge です（ローカルネットワークの扱いがブラウザごとに違います）
- アドレスは `http://127.0.0.1:8765` 固定です。ポートを変えるときは `config.json` の `server.port` と `lib/tenmatsu/client.ts` の `TENMATSU_BASE_URL` の**両方**を直して再デプロイしてください
- プレビュー用のVercelデプロイはURLが毎回変わり `allowed_origins` に入らないため繋がりません。`allowed_origins` に登録した本番URLで使ってください
- PC側のツールが古いと、**件数の指定と完了フラグは使えません**（件数欄は出ず、チェック欄は「－」になります）。`~/tenmatsu-dl/` を更新してください

## 処理速度

実測（見本5ペア、2026-08-26）:

| | 変更前 | 変更後 |
| --- | --- | --- |
| 工事区分の判定 | 平均13.6秒 | 平均**2.3秒** |
| 要約の生成 | 平均9.6秒 | 平均**1.1秒** |
| 5ペアの合計 | 約2分 | **10秒前後** |

内訳を測ると、PDFの解析・結合・画像化（ローカル処理）は5ペア合計で約3秒しかかからず、残りはすべてGeminiの応答待ちでした。そこで次の3点で短縮しています。

1. **思考トークンの抑制** — Gemini 3.x系は既定で「思考」してから答えるため遅くなります。`thinkingLevel: MINIMAL` を指定し、判定精度を落とさずに待ち時間を削減（見本5件の工事区分は変更前後どちらも正解5/5）
2. **モデルの選定** — 画像認識は精度が要るので flash系（実測5/5）、要約は速くて品質も十分な flash-lite系。別モデルにすることで無料枠のクォータも分散されます
3. **並列化** — 1ペア内で「要約」と「工事区分」を同時に実行し、さらにペア自体も3件ずつ並列処理（巨大PDFが重なってメモリを圧迫しないよう、同時に扱う合計サイズにも上限あり）

無料枠の上限に当たった場合は、無駄なリトライをせず即座に警告を出して手動入力に切り替わります（待たされません）。

## 要約エンジン（点検内容 / アフター受付内容）

- `GEMINI_API_KEY` を設定すると **Gemini（無料枠）** で自然な要約を生成します（同じキーで工事区分の画像認識も有効になります）。
  1. <https://aistudio.google.com/apikey> で無料のAPIキーを取得（クレジットカード不要）
  2. リポジトリ直下に `.env.local` を作成: `GEMINI_API_KEY=取得したキー`
  3. `npm run dev` を再起動
  - 使用モデルは `.env.local` の `GEMINI_VISION_MODELS`（画像認識）と `GEMINI_SUMMARY_MODELS`（要約）で変更できます。いずれもカンマ区切りで複数指定でき、1日の上限に達したモデルは自動で飛ばされます。「This model ... is no longer available」というエラーが出たら、ここを新しいモデル名に差し替えてください
- キー未設定・API失敗時は自動で**ルールベースの定型要約**にフォールバックします（結果に「定型要約」バッジが付きます）。
- 「この書き方を学習」で覚えた過去の例があれば、今回の入力に近いものを手本としてプロンプトに添えます（[書き方を学習させる](#書き方を学習させる)）。定期点検・アフターメンテナンスのどちらでも使えます。
- 出力は**不具合の事象のみ**です。お客様の要望（補修希望・見積もり希望・無償対応の希望など）と社内の対応方針（弊社継続対応・別日対応・是正不可など）は含めません。
- **事象ごとに①②③を付けて改行**して並べます（1件だけのときは番号なし）。Excelにはセル内改行として貼り付きます。

  ```
  ①1階洋室天井のクロスに凹凸
  ②2階リビング壁のクロスに浮き・隙間
  ③2階階段ササラ仕上げの剥がれ
  ```

  番号付けと改行はサーバー側で組み立てているため、Gemini・ルールベースのどちらでも同じ形式になります（LLMの表記揺れに影響されません）。点検員のメモ（立ち会いや連絡先の申し送りなど不具合でないもの）は番号を付けず末尾に「メモ: …」の行として付きます。
- 備考に要望しか書かれていない項目（例: 電動ブラインドを取り付けたい）は事象が無いため、要約に載りません。工事区分の列や結合PDFには影響しません。
- Geminiへ送信されるのは、**個人情報を伏字化した不具合テキスト**（要約用）、**学習した書き方**（伏せ字済みの入力と本文）、**署名・電話番号を切り落とした点検シート画像**（工事区分用）、**施主名の漢字**（メール文のカナ読み推定用）です。住所・契約番号・電話番号・PDF本体は送信されません。ただし無料枠の送信データはGoogleのサービス改善に利用され得る点にご留意ください。

### アフターメンテナンスの受付内容

コールセンターの受付メモは自由文なので、専用のプロンプトで「不具合の事象だけ」を取り出します（要望・訪問日程・折り返しの約束・挨拶は落とします）。送信前に、選んでいるお客様の氏名・カナ・電話番号・住所・メールアドレスをブラウザ内で伏せ字に置き換えます（顧客レコードが手元にあるので確実に消せます）。「この書き方を学習」で覚えた過去の例があれば、今回のメモに近いものを手本としてプロンプトに添えます（[書き方を学習させる](#書き方を学習させる)）。キー未設定・通信できないときは、ブラウザ内で文を分けて段取りの文を落とすだけの定型処理になります（[lib/summarize/inquiry.ts](lib/summarize/inquiry.ts)）。

## デプロイ（Vercel）

ローカル実行が基本ですが、チームで共有する場合は Vercel にデプロイできます（PDFの解析・結合はブラウザ内で完結するため、サーバー側の構成変更は不要です）。

1. <https://vercel.com> にGitHubアカウントでサインアップし、「Add New… → Project」でこのリポジトリを Import する（フレームワークは Next.js が自動検出されます）
2. 「Environment Variables」に次を設定する
   - `GEMINI_API_KEY` … Gemini APIキー（要約・工事区分の画像認識に使用）
   - `APP_PASSWORD` … **必ず設定してください。** 設定すると全ページ・APIがパスワードで保護され、URLを知っているだけでは使えなくなります（ユーザー名は `APP_USER`、省略時 `user`）
   - `APP_SESSION_DAYS` … 任意。ログインを保持する日数（省略時30日）
   - `GEMINI_MODEL` … 任意（省略時 `gemini-3.6-flash`）
3. 「Deploy」を押す。以後は `main` に push するたびに自動で再デプロイされます

注意点:

- 顧客の個人情報を扱うため、`APP_PASSWORD` 無しで公開しないでください。認証情報は関係者にだけ共有します

### ログイン

`APP_PASSWORD` を設定すると、未ログインのアクセスは**ログイン画面**（`/login`）に飛びます。

- ブラウザ標準の認証ダイアログではなく**通常の入力フォーム**です。パスワードマネージャーが保存・自動入力できます（ユーザー名の欄には `APP_USER` の値が最初から入っています）
- 一度ログインすると、**同じブラウザでは30日間ログインしたまま**です（ブラウザを閉じても残ります）。日数は `APP_SESSION_DAYS` で変えられます
- 共有の端末では、作業後に画面右上の**「ログアウト」**を押してください
- 保存されるのは**有効期限と署名だけ**のクッキーで、パスワードそのものは入りません（JavaScriptからも読めません）。`APP_PASSWORD` を変えると、それまでのログインはすべて無効になります
- スクリプトから叩くときのために、**Basic認証のヘッダーも引き続き受け付けます**（`curl -u user:パスワード ...`）
- APIはリダイレクトせず 401 を返します
- Vercel の無料プラン（Hobby）は**非商用・個人利用が規約上の前提**です。業務利用が続くなら Pro プラン（有料）か、商用利用可の他ホスティングを検討してください
- APIルートは実行時間上限を60秒（`maxDuration`）に設定し、リトライを含む処理はその内側（要約30秒・画像認識45秒）で必ず打ち切ってフォールバックを返します

## テスト

```bash
npm test
```

顛末書のローカルサーバーとの通信は、実サーバーを起動せず偽の `fetch` を渡して確かめています（`tests/tenmatsu-client.test.ts`）。一覧の絞り込み・完了の非表示・件数の内訳は純関数に出してあり（`lib/tenmatsu/list-view.ts`）、組み合わせを `tests/tenmatsu-list-view.test.ts` で固定しています。画面の見た目と操作はPC側の**デモモード**（`python server.py --demo`、架空データ・楽楽精算に接続しない）で確認します。

見本PDF（`写真報告書_例/`・`点検報告書_例/`）に対するゴールデンテストを含みます。**見本PDFと期待値フィクスチャ（`tests/fixtures/`）は実在の個人情報を含むためgit管理していません**（`.gitignore` 済み）。これらが無い環境では該当テストは自動でスキップされます（`SAMPLE_PDF_DIR` / `SAMPLE_INSPECTION_DIR` で場所の指定も可能）。

期待値フィクスチャは、抽出結果を目視確認した上で次のように再生成できます:

```bash
npm run dump -- "写真報告書_例/(ファイル名).PDF" --parse > "tests/fixtures/expected/(日付)_(姓).json"
```

## テンプレートが変わったとき

抽出は写真報告書テンプレートの実測座標（`lib/pdf/constants.ts`）に基づきます。レイアウトが変わって抽出できなくなった場合は、

```bash
npm run dump -- "写真報告書のパス.pdf"          # トークンと座標をダンプ
npm run dump -- "写真報告書のパス.pdf" --parse  # パース結果を確認
```

で座標を再計測し、`lib/pdf/constants.ts` を更新してください。未知のレイアウトは誤値を出さず「抽出失敗（赤セル）」として手動入力を促します。

完了報告書の様式（`完了報告書_例/完了報告書（原紙）.xlsx`）が変わったときは、同梱テンプレートを作り直します。

```bash
python3 scripts/build_report_template.py   # 3シートに絞り、個人情報を除いて public/report/ へ
python3 scripts/build_report_fonts.py      # Noto Sans JP を取得・サブセット・gzip
python3 scripts/extract_report_geometry.py # 見本PDFから罫線・ラベル位置を再抽出 (テストの基準)
npm test                                    # tests/report-*.test.ts で崩れを検出
```

見た目を確認するときは架空データでPDFを書き出して見本と比べます。

```bash
npx tsx scripts/dump-report.mts .cache/report --items 1
npx tsx scripts/dump-report.mts .cache/report --items 6
python3 scripts/report_visual_diff.py      # 罫線のずれを数値で確認 (.cache/report/*-side.png)
```

罫線の座標は `lib/report/metrics.ts`、セルの配置は `lib/report/layout/{main-sheet,appendix-sheet}.ts` にあります。
